# Как использовать шаблон AGENTS.md

`AGENTS.md` — это рабочий контракт между владельцем репозитория и агентом. Хороший файл не пересказывает README, а заранее отвечает на вопросы: что считать источником истины, что нельзя ломать, как выбирать задачу, какие проверки обязательны и когда агент должен остановиться.

## Быстрый порядок

1. Скопируйте [AGENTS.template.md](AGENTS.template.md) в корень нового репозитория под именем `AGENTS.md`.
2. Заполните все `<PLACEHOLDER>`.
3. Удалите неприменимые примеры, но не разделы про безопасность, проверки и stop conditions.
4. Добавьте реальные команды установки, тестов, сборки и lint.
5. Зафиксируйте 5–12 архитектурных инвариантов конкретного продукта.
6. Укажите один канонический каталог документации и одну очередь задач.
7. Добавляйте вложенные `AGENTS.md` только там, где подкаталог действительно требует дополнительных правил.

## Что делает AGENTS.md полезным

- даёт точный порядок чтения;
- отделяет текущую документацию от исторической;
- запрещает агенту незаметно расширять scope;
- заставляет проверять реальный код до реализации;
- закрепляет источники истины и trust boundaries;
- перечисляет реальные команды проверки;
- объясняет правила миграций, секретов и внешних действий;
- задаёт формат результата и stop conditions.

## Что туда не стоит помещать

- секреты и токены;
- длинную историю продукта;
- абстрактные советы без проверяемого действия;
- команды, которые не работают в репозитории;
- правила, противоречащие CI или фактической архитектуре;
- требование автоматически коммитить, пушить или деплоить без явного разрешения владельца.

Пересматривайте файл после изменения архитектуры, структуры каталогов, CI или процесса релизов.
