# Цель

Не позволять production-маршруту `materials_rnd` преждевременно завершаться через `webBuildPhase` или создавать финальную лекцию через `assembleLecture`.

При этом профиль `generic` должен сохранить оба прежних сценария без функциональных изменений.

# Зависимость

M0.3 принята владельцем и имеет статус `accepted`. Worker уже вызывает единый profile router, а `materials_rnd` входит в отдельную state machine с временным legacy bridge.

# Зачем это нужно

В существующем engine веб-сборка может вернуть результат раньше planner и DAG. Это допустимое старое поведение для `generic`, но для Materials R&D такой выход обходит будущие контракты, human gates и научные проверки. Финальный lecture-builder также создаёт артефакт другого назначения и не должен запускаться в материаловедческой ветке.

# Входит в задачу

1. Внутри `engine.ts` выделить неизменяемую внутреннюю политику legacy-фаз.
2. Оставить экспорт `orchestrate` generic-entrypoint с разрешёнными `webBuildPhase` и `assembleLecture`.
3. Добавить отдельный materials bridge-entrypoint с запрещёнными `webBuildPhase` и `assembleLecture`.
4. Политика выбирается самим entrypoint, а не значением внешнего payload и не эвристикой текста.
5. Политику нельзя передать из renderer, IPC, WorkerData, `OrchestrateOpts` или `spawnSub`.
6. Переключить default-executor `materialsProfileStateMachine` со старого generic-entrypoint на защищённый materials bridge.
7. Не менять остальной порядок engine: research, planner, tree, modes, human review и aggregate продолжают работать как раньше.
8. Добавить production-routing spy-тесты, которые вызывают реальный `orchestrateWorkflowProfile`.
9. Проверить, что root materials-run не вызывает обе запрещённые функции даже в условиях, где generic обязательно вызвал бы их.
10. Проверить сохранение обоих generic-сценариев: ранний webBuild-return и финальная сборка lecture.

# Не входит в задачу

- полноценный materials engine или доменная state machine;
- отключение `researchPhase`;
- удаление `LECTURE_FORGE_PLAYBOOK` из подсказки planner;
- изменение planner, DAG, modes, aggregate или human review;
- изменение самих `webbuild.ts` и `lecture.ts`;
- новые IPC, UI или Zod-контракты;
- `ResearchGoalV1`, PlanPreview, Human Gate и version store;
- FakeRuntime M0.5;
- агенты, RAG, память, научные модели и инструменты;
- fallback материаловедческого маршрута на generic при ошибке;
- исправление сторонних TypeScript-ошибок;
- сборка установщика.

# Разрешённые файлы

- `src/main/orchestrator/engine.ts` — только выделение phase policy и двух entrypoint;
- `src/main/orchestrator/materialsProfileStateMachine.ts` — только замена default legacy executor;
- новый тест M0.4 в `src/main/orchestrator/__tests__/`;
- при необходимости существующие regression-тесты, только для уточнения generic-инварианта;
- документы статусов, README и changelog.

Не изменять `profiles.ts`, worker, contracts, profile propagation, renderer, preload, main IPC, research, webbuild, lecture, planner, mode selector, modes, registry, БД и конфигурацию сборки.

# Инварианты

## Generic webBuild

```text
profile router → generic entrypoint
→ root run вызывает webBuildPhase
→ если webBuild вернул результат, он остаётся ранним результатом run
```

## Generic lecture

```text
profile router → generic entrypoint
→ scientific = true, webBuild не завершил run
→ planner/DAG
→ assembleLecture вызывается как раньше
```

## Materials R&D

```text
profile router → materials state machine → protected materials bridge
→ research разрешён
→ webBuildPhase не вызывается
→ planner/DAG/aggregate продолжаются
→ assembleLecture не вызывается
```

## Ошибка

Ошибка planner, mode или aggregate не разрешает повторный запуск через generic и не включает запрещённые фазы как fallback.

# Критерии приёмки

1. Production `generic` по-прежнему связан со старым поведением engine.
2. Production `materials_rnd` использует защищённый bridge через state machine.
3. `webBuildPhase` не вызывается для root materials-run.
4. `assembleLecture` не вызывается для scientific materials-run.
5. Materials-run доходит до planner даже если mock webBuild подготовлен вернуть ранний sentinel.
6. Generic-run по-прежнему возвращает webBuild sentinel по identity и не вызывает planner после раннего результата.
7. Generic scientific-run по-прежнему вызывает `assembleLecture`, если webBuild не завершил run.
8. Политика фаз не содержится во внешних или межпроцессных контрактах.
9. Router, worker и контракты M0.1–M0.3 не изменены.
10. Research, planner, modes, webbuild и lecture implementations не изменены.
11. Нет fallback materials → generic.
12. Spy-тесты используют production router и не обращаются к сети или LLM.
13. Все существующие регрессии остаются зелёными.
14. `npm test` и `npm run build` проходят.
15. Новых TypeScript-ошибок нет.

# Отчёт о выполнении — 2026-08-28

Карточка реализована, проверена и принята владельцем перед началом M0.5.

## Что реализовано

- В `engine.ts` введена приватная неизменяемая политика двух legacy-фаз.
- Публичный generic-entrypoint `orchestrate` использует политику `webBuild = on`, `lecture = on`.
- Новый фиксированный `orchestrateMaterialsLegacyBridge` использует политику `webBuild = off`, `lecture = off`.
- Политика не добавлялась в `OrchestrateOpts`, WorkerData, IPC или renderer и не может быть изменена входным запросом.
- Production materials state machine переключена на защищённый bridge без изменения переходов, trace и обработки ошибок.
- Остальная логика engine, включая research, planner, DAG, modes, human review и aggregate, сохранена.
- Устаревшая generic-регрессия больше не утверждает, что прямой webBuild является поведением обоих профилей.

## Матрица фактических вызовов

| Production-профиль | research | webBuildPhase | planner | assembleLecture |
|---|---:|---:|---:|---:|
| `generic`, ранний webBuild-result | 1 | 1 | 0 | 0 |
| `generic`, scientific и `webBuild.ran = false` | 1 | 1 | 1 | 1 |
| `materials_rnd`, scientific | 1 | 0 | 1 | 0 |
| `materials_rnd`, ошибка planner | 1 | 0 | 1 с ошибкой | 0 |

Материаловедческий тест запускается через реальный `orchestrateWorkflowProfile`, проходит state machine и завершается реальным aggregate. Поэтому нулевые вызовы запрещённых фаз не являются следствием no-op или фиктивного success.

## Проверки

- Целевая production spy-матрица и профильные регрессии: `4` файла, `34` теста — успешно.
- Полный набор проекта: `9` файлов, `77` тестов — успешно.
- Production build main, preload и renderer — успешно.
- Общий TypeScript-аудит показывает только ранее зафиксированные baseline-ошибки в `research.ts`, PDF worker и старых участках `FlowNodeShapeUtil.tsx`; новых ошибок M0.4 нет.
- Интерактивный Electron smoke оставлен шагом ревьюера; установщик не входил в scope.

## Подтверждение generic-регрессии

Тесты отдельно доказывают identity раннего webBuild-результата и сохранение финального вызова `assembleLecture` после scientific planner. Реализации `webbuild.ts`, `lecture.ts`, research, planner и modes не изменялись.

## Ограничение

`M0.4 закрывает только два legacy bypass; materials_rnd всё ещё использует research, planner, generic DAG/modes и aggregate до появления доменного engine.`
