# Цель

Создать точную и машинно проверяемую границу качества после E0: успешные тесты и production build, разрешённый набор уже существующих TypeScript-диагностик и воспроизводимое описание toolchain.

После M0.6 новая или изменившаяся TypeScript-ошибка не может быть объявлена «старой» без явного изменения нормативного manifest и отдельного объяснения в карточке.

# Зависимость

M0.5 принята владельцем и имеет статус `accepted`. Детерминированный FakeRuntime и полный набор из 92 тестов доступны без сети и внешних сервисов.

# Входит в задачу

1. Зафиксировать версии Node.js, npm, TypeScript, Vitest, Vite, electron-vite и Electron.
2. Зафиксировать Git HEAD/branch как контекст, явно указав, что рабочее дерево содержит незакоммиченные результаты M0.1–M0.5 и HEAD не идентифицирует весь baseline.
3. Зафиксировать SHA-256 `package.json`, `package-lock.json`, `tsconfig.json`, `electron.vite.config.ts` и файлов с разрешёнными диагностическими долгами.
4. Зафиксировать итоговый список test-файлов, suites, tests, passed/failed/skipped после добавления guard.
5. Зафиксировать успешную сборку main, preload и renderer.
6. Создать normative JSON manifest с точным мультимножеством разрешённых `tsc`-диагностик:
   - project-relative file;
   - код TypeScript;
   - нормализованное основное сообщение;
   - допустимое количество;
   - line/column и semantic anchor только для ревью.
7. Добавить test-only parser/comparator и Vitest guard, который запускает локальный TypeScript с `--noEmit --pretty false` и сравнивает реальный результат с manifest.
8. Guard проверяет версию TypeScript и SHA-256 `tsconfig.json` до сравнения.
9. Добавить негативные unit-сценарии: новая/изменённая диагностика и исчезнувшая разрешённая диагностика обнаруживаются.
10. Обновить `CLAUDE.md` и execution playbook: расплывчатое разрешение игнорировать ошибки заменяется ссылкой на точный baseline.
11. Создать понятный Markdown-отчёт и синхронизировать документы с Obsidian.

# Не входит в задачу

- исправление 13 существующих TypeScript-диагностик;
- добавление новой ошибки в baseline;
- wildcard по целому файлу, коду ошибки или каталогу;
- изменение production-кода, `tsconfig.json`, зависимостей, npm scripts или Vitest/build-конфигурации;
- CI workflow, pre-commit hook или отдельный release gate;
- сборка установщика и интерактивный Electron smoke;
- очистка, commit, reset или иная нормализация грязного рабочего дерева;
- переход к M1.1.

# Нормативная политика сравнения

```text
fingerprint = normalized project-relative file + TS code + normalized primary message
actual multiset == allowed multiset
```

- Line/column и semantic anchor помогают ревьюеру, но не являются ключом: обычный сдвиг строк не превращает старую ошибку в новую.
- Новый fingerprint или превышение `allowed_count` — регрессия.
- Исчезнувший fingerprint или уменьшение количества — улучшение, которое также останавливает guard до удаления долга из manifest. Это не позволяет исправленной ошибке вернуться незаметно.
- Смена TypeScript или `tsconfig.json` останавливает guard до отдельного пересмотра baseline.
- Добавлять новые разрешения в последующих карточках запрещено; manifest можно только сокращать при исправлении либо менять отдельной явно принятой baseline-карточкой.
- Падающие тесты или build никогда не становятся baseline.

# Критерии приёмки

1. M0.5 имеет статус `accepted`.
2. Manifest является валидным JSON и содержит ровно 13 разрешённых диагностик в трёх файлах без wildcard.
3. Два последовательных raw typecheck дают один и тот же мультимножество fingerprints.
4. Реальный baseline guard завершается успешно при прямом запуске локального TypeScript CLI с exit code `2`, если присутствуют только 13 разрешённых диагностик.
5. Негативные unit-тесты обнаруживают добавленную/изменённую и исчезнувшую диагностику.
6. Версия TypeScript и hash `tsconfig.json` проверяются guard до diagnostic comparison.
7. Итоговые `npm test` и `npm run build` проходят.
8. Итоговый Markdown перечисляет test inventory, build, environment, hashes, 13 диагностик и правила будущего сравнения.
9. В production нет изменений M0.6 и ссылок на test-only helper.
10. Документы репозитория и Obsidian совпадают по SHA-256.

# Автоматические проверки

```text
npx vitest run src/main/orchestrator/__tests__/typecheckBaseline.test.ts
npm test
npm run build
npx tsc --noEmit --pretty false
```

Последняя команда через PowerShell может отображаться как общий code `1`. Normative guard не использует shell или `npx`: он запускает локальный `node_modules/typescript/bin/tsc` через `process.execPath`, где ожидаемый код compile diagnostics равен `2`. Успешным gate является точное совпадение прямого результата с manifest.

# Правила остановки

Остановиться и запросить решение владельца, если:

- M0.5 нельзя считать принятой;
- появился четырнадцатый fingerprint или изменилось сообщение существующей диагностики;
- tests или build падают;
- требуется менять production, `tsconfig`, зависимости или версии инструментов;
- manifest нельзя проверить без сетевого обращения;
- требуется commit/reset/очистка пользовательского рабочего дерева;
- задача расширяется до исправления долгов или M1.1.

## Реализованные артефакты

- Normative JSON manifest хранит environment, resolved toolchain, Git context, test/build inventory, config/source hashes и точный diagnostic multiset.
- Человекочитаемый `10-engineering-quality-baseline.md` объясняет каждую группу долга и процедуру следующих карточек.

- TypeScript version и hash `tsconfig.json` проверяются до запуска компилятора.
- Отдельные negative cases доказывают отклонение added/changed и missing diagnostics; global `error TS…` без file/line также не может пройти незамеченным.
- `CLAUDE.md` и execution playbook больше не разрешают расплывчато игнорировать «несколько старых ошибок».
