# Цель

Добавить единственную доверенную точку маршрутизации профилей между worker и движком:

```text
worker
  → profile router
      ├─ generic       → существующий engine без изменения поведения
      └─ materials_rnd → отдельная начальная state machine профиля
```

На M0.3 материаловедческая state machine только фиксирует собственный жизненный цикл и временно передаёт выполнение существующему engine. Удаление `webBuildPhase` и lecture-builder из материаловедческого пути — отдельная карточка M0.4.

# Зависимость

M0.2 принята владельцем и имеет статус `accepted`. Каждый worker уже получает проверенный `WorkflowProfile`, а trace централизованно маркируется профилем запуска.

# Зачем это нужно

Сейчас профиль переносится через систему, но оба значения напрямую вызывают одну функцию. До появления материаловедческих контрактов, human gates и агентов нужна явная граница, в которой дальнейшие этапы смогут заменять только ветку `materials_rnd`, не затрагивая стабильный generic-workflow.

# Входит в задачу

1. Создать `src/main/orchestrator/profiles.ts` как единственную точку выбора runner по `WorkflowProfile`.
2. Передавать в router уже проверенный `OrchestrateOpts`; router не угадывает профиль и не назначает default.
3. Маршрут `generic` направить прямо в существующую `orchestrate` из `engine.ts`.
4. Маршрут `materials_rnd` направить в отдельную функцию начальной state machine.
5. Создать минимальную state machine со строгими переходами:

   `selected → legacy_bridge_running → finished | failed`.

6. На каждом переходе state machine создавать объяснимый системный trace-черновик. Worker добавляет к нему доверенный `workflow_profile` по механизму M0.2.
7. Временный `legacy_bridge_running` вызывает существующий engine ровно один раз и возвращает его `TaskResult` без подмены статуса, confidence, issues или output.
8. При исключении runner переводить машину в `failed`, фиксировать переход и пробрасывать исходную ошибку наверх.
9. Заменить прямой вызов engine в worker на вызов profile router.
10. Добавить unit-тесты router, переходов state machine, делегирования и ошибки.

# Не входит в задачу

- изменение алгоритма существующего `engine.ts`;
- запрет или обход `researchPhase`, `webBuildPhase`, planner, modes и lecture-builder;
- полноценные состояния материаловедческого проекта `draft → clarification → approval`;
- `ResearchGoalV1`, `PlanPreview`, `CompiledGraph` и Human Gate;
- новые IPC-команды `materials:*`;
- UI-изменения;
- агенты, RAG, граф знаний, научные модели и инструменты;
- автоматический выбор профиля по тексту;
- фиктивный успешный `TaskResult` для materials;
- изменение контрактов M0.1–M0.2;
- исправление сторонних TypeScript-ошибок;
- сборка установщика.

# Разрешённые файлы

- новый `src/main/orchestrator/profiles.ts`;
- новый `src/main/orchestrator/materialsProfileStateMachine.ts`;
- `src/main/orchestrator/worker.ts` — только замена точки вызова;
- новые тесты маршрутизации в `src/main/orchestrator/__tests__/`;
- существующий generic regression-тест, только если нужна дополнительная проверка неизменности;
- документы статусов задач, README и changelog.

Не изменять `engine.ts`, `research.ts`, `webbuild.ts`, `lecture.ts`, `planner.ts`, `modeSelector.ts`, `modes/*`, renderer, preload, main IPC, registry и базу данных.

# Инварианты

## Generic

```text
workflowProfile = generic
→ router выбирает существующий orchestrate
→ materials state machine не вызывается
→ все прежние research/webBuild/planner/modes/lecture правила сохраняются
```

## Materials R&D на M0.3

```text
workflowProfile = materials_rnd
→ router выбирает отдельную state machine
→ selected → legacy_bridge_running
→ существующий engine временно выполняется один раз
→ finished или failed
```

Этот bridge является явным переходным состоянием, а не окончательной материаловедческой реализацией.

## Ошибка

```text
runner выбрасывает ошибку
→ state machine фиксирует failed
→ ошибка не превращается в success или partial
→ worker формирует существующий failure-конверт
```

## Fail closed

Неизвестный профиль невозможен после main-валидации M0.2. Если он всё же попал в router из-за программной ошибки, выполнение завершается явным исключением; fallback на `generic` запрещён.

# Критерии приёмки

1. Worker больше не импортирует и не вызывает engine напрямую.
2. `profiles.ts` содержит исчерпывающее сопоставление двух значений `WorkflowProfile`.
3. `generic` вызывает только существующий engine и возвращает его результат без изменений.
4. `materials_rnd` вызывает только отдельную state machine.
5. State machine допускает только заявленные переходы.
6. Временный bridge вызывает существующий engine ровно один раз и возвращает исходный результат.
7. Каждый переход создаёт trace с предыдущим и новым состоянием.
8. Исключение runner фиксирует `failed` и пробрасывается без подмены.
9. Неизвестный профиль не получает fallback.
10. `engine.ts`, research, webBuild, planner, modes и lecture не изменены.
11. Generic regression остаётся зелёной.
12. Позитивные и негативные тесты маршрутизации проходят без сети и LLM.
13. `npm test` и `npm run build` проходят.
14. В новых файлах нет TypeScript-ошибок.

# Отчёт о выполнении — 2026-08-28

Карточка реализована, проверена и принята владельцем перед началом M0.4.

## Что реализовано

- Worker вызывает единственную production-точку `orchestrateWorkflowProfile` вместо прямого вызова engine.
- `profiles.ts` содержит замороженное исчерпывающее сопоставление обоих значений `WorkflowProfile`.
- `generic` связан непосредственно с существующей `orchestrate`; её код не менялся в M0.3.
- `materials_rnd` связан с отдельной `runMaterialsProfileStateMachine`.
- State machine допускает только переходы `selected → legacy_bridge_running → finished | failed`.
- Переходы создают системные trace-черновики с учётом branch; механизм M0.2 добавляет доверенный профиль.
- Legacy bridge вызывает существующий engine ровно один раз и сохраняет identity результата и ошибки.
- Ошибка аварийного trace не может скрыть исходную ошибку исполнителя.
- Неизвестный внутренний профиль завершается явной ошибкой до вызова любого runner.

## Таблица маршрутизации

| Вход router | Выбранный runner | Другой runner | Fallback |
|---|---|---|---|
| `generic` | существующий engine, ровно один вызов | materials — 0 | нет |
| `materials_rnd` | materials state machine, ровно один вызов | generic-ветка router — 0 | нет |
| неизвестное значение | не вызывается | не вызывается | запрещён, явная ошибка |

## Проверки

- Целевая матрица маршрутизации и M0.2-регрессии: `4` файла, `34` теста — успешно.
- Полный набор проекта: `8` файлов, `74` теста — успешно.
- Production build main, preload и renderer — успешно.
- Общий TypeScript-аудит показывает только ранее зафиксированные baseline-ошибки в `research.ts`, PDF worker и старых участках `FlowNodeShapeUtil.tsx`; `profiles.ts`, `materialsProfileStateMachine.ts` и новые тесты не добавили ошибок.
- Интерактивный Electron smoke оставлен шагом ревьюера; сборка установщика не входила в scope.

## Подтверждение generic-регрессии

`engine.ts`, research, webBuild, planner, mode selector, modes и lecture не изменялись в M0.3. Production-сопоставление `generic → orchestrate` проверяется отдельно и заморожено от случайной замены во время выполнения.
