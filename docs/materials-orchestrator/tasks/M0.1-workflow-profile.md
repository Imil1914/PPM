# Цель

Создать один общий runtime-проверяемый контракт профиля оркестрации: `generic | materials_rnd`.

Задача не должна менять фактический путь запуска приложения. Она создаёт фундамент для M0.2.

# Зачем это нужно

Существующий оркестратор должен продолжить работать как `generic`, а новая материаловедческая логика должна подключаться отдельно. Если main, worker и renderer заведут разные строковые значения, профиль станет ненадёжным. Поэтому сначала нужен один общий контракт.

# Состояние до начала

- В `src/main/orchestrator/contracts.ts` профиля нет.
- Текущий оркестратор всегда использует универсальный путь.
- Zod 4 уже установлен.
- Vitest ищет `src/**/*.{test,spec}.{ts,tsx}`.
- Общего каталога `src/shared/orchestrator/` пока нет.

# Входит в задачу

1. Создать чистый общий модуль, рекомендуемый путь:
   `src/shared/orchestrator/workflowProfile.ts`.
2. Экспортировать Zod-схему:
   `WorkflowProfileSchema = z.enum(['generic', 'materials_rnd'])`.
3. Экспортировать TypeScript-тип через `z.infer`.
4. Экспортировать `DEFAULT_WORKFLOW_PROFILE = 'generic'`.
5. Экспортировать функцию безопасного разбора:
   - `undefined` и `null` дают `generic`;
   - допустимые строки возвращаются без изменения;
   - неизвестная строка не заменяется молча на default, а возвращает ошибку Zod.
6. Добавить unit-тесты.

# Не входит в задачу

- изменение `orch:start`;
- изменение `WorkerData`;
- добавление поля в renderer-ноду;
- UI выбора профиля;
- materials state machine;
- изменение planner, engine, registry или modes;
- миграция сохранённых досок;
- добавление Python/Pydantic.

# Разрешённые файлы

- новый `src/shared/orchestrator/workflowProfile.ts`;
- новый `src/shared/orchestrator/__tests__/workflowProfile.test.ts`;
- при доказанной необходимости — минимальная правка конфигурации импорта, но сначала остановиться по правилу ниже.

Не изменять существующий runtime только ради демонстрации нового типа.

# Контракт

Допустимо:

```ts
parseWorkflowProfile(undefined) === 'generic'
parseWorkflowProfile(null) === 'generic'
parseWorkflowProfile('generic') === 'generic'
parseWorkflowProfile('materials_rnd') === 'materials_rnd'
```

Недопустимо:

```ts
parseWorkflowProfile('materials')
parseWorkflowProfile('GENERIC')
parseWorkflowProfile(123)
parseWorkflowProfile({})
```

Для недопустимых входов функция должна выбросить или вернуть стандартную структурированную ошибку Zod согласно выбранному API. Она не должна молча превращать их в `generic`.

# Критерии приёмки

1. Схема принимает ровно два значения.
2. Тип выводится из Zod, а не дублируется вручную union-типом.
3. Отсутствующее значение получает default `generic`.
4. Неизвестное значение отклоняется.
5. Модуль не импортирует Electron, renderer, Node filesystem или сетевые зависимости.
6. Тесты покрывают оба допустимых значения, `undefined`, `null` и не менее четырёх недопустимых значений.
7. `npm test` проходит.
8. `npm run build` проходит.
9. Поведение приложения не изменилось.

# Ручной smoke

Для этой чистой задачи UI-smoke не требуется. Нужно подтвердить, что build собирает main, preload и renderer с новым shared-модулем.

# Поведение при ошибке

- Ошибка схемы остаётся стандартной ошибкой Zod.
- Никакой автоматический fallback для неизвестной строки не добавляется.
- Default применяется только при отсутствии значения.

# Правила остановки

Остановиться и запросить решение владельца, если:

- общий модуль нельзя безопасно импортировать из main и renderer без изменения архитектуры сборки;
- требуется дублировать Zod-схему в двух местах;
- задача неожиданно требует миграции пользовательских данных;
- для прохождения build приходится менять unrelated configuration.
