# Цель

Создать единый строгий TypeScript/Zod-модуль, который на runtime проверяет все V1-объекты из разделов 3–16 нормативного документа `04-data-and-api-contracts.md`. Каждая схема является единственным источником своего TypeScript-типа через `z.infer`; параллельные ручные интерфейсы не создаются.

# Зависимость

M0.6 принята. До и после M1.1 обязательны точный TypeScript baseline, полный тестовый набор и production build.

# Канонический источник

Для M1.1 точные имена и shapes берутся из `04-data-and-api-contracts.md`. Документы 05, 07 и 08 задают поведение и fixtures, но местами используют будущие или разговорные названия (`SourceSpan`, `PlanPreview`, расширенный YAML AgentSpec/ToolSpec). Эти названия нельзя превращать в новые persisted V1-контракты без отдельного нормативного решения.

# Входит в задачу

1. Создать каталог `src/main/orchestrator/materials/contracts/` и модули:
   - `common.ts` — примитивы, общие enum и `StructuredFailureV1`;
   - `goal.ts` — цель, свойства, вопросы и допущения;
   - `graph.ts` — plan draft, node spec и compiled graph;
   - `evidence.ts` — источники, fragments, claims, context и knowledge query;
   - `feedback.ts` — feedback, change request, dependency edge и invalidation;
   - `agents.ts` — agent spec/run/result и capability request;
   - `tools.ts` — tool spec/invocation/call и validation report;
   - `materials.ts` — observations, predictions, compositions, routes, candidates и DoE;
   - `package.ts` — human gates, critique, experiment package и artifact manifest;
   - `index.ts` — публичные exports без побочных эффектов.
2. Все фиксированные объекты должны быть strict: неизвестные поля отклоняются на каждом структурированном уровне.
3. Проверить локальные инварианты, однозначно доступные без БД и доменных сервисов:
   - непустые trimmed ID, имена контрактов и текстовые обязательные поля;
   - UTC ISO timestamp;
   - `version >= 1`, целые неотрицательные счётчики, положительные timeout и execution limits;
   - только конечные числа и непустая единица физической величины;
   - согласованный `IntervalQuantity` в общей единице (`min <= target <= max`, когда границы заданы);
   - confidence и fractions в `[0, 1]`, неотрицательные weights и information value;
   - хотя бы одно target property и route family в ResearchGoal;
   - required и forbidden elements не пересекаются;
   - `reported_fact` содержит хотя бы один `evidence_ref`;
   - `approved_for_experiment` содержит `approved_decision_ref`;
   - human decision `request_changes` содержит хотя бы один адресный change request;
   - ToolSpec с `side_effects: ['none']` не смешивает `none` с реальными side effects.
4. Добавить полноценные валидные fixtures для каждой экспортированной V1 schema. Полный `ResearchGoalV1` достраивается из смыслового примера эталонной алюминиевой пластины в документе 08 и проходит настоящий `.parse()`.
5. Добавить table-driven позитивные и отрицательные contract-тесты, включая обязательные случаи M1.1: отсутствующая единица или test temperature, `NaN`/`Infinity`, неизвестный enum, лишнее поле, reported fact без provenance, prediction без ModelCard, package без critique или поля risks и нарушенные локальные cross-field-инварианты.

# Явно не входит

- JSON Schema 2020-12 export и roundtrip — M1.2;
- миграции версий — M1.3;
- проверка существования `VersionRef`, immutable/version repository и optimistic concurrency — M1.4–M1.6;
- cycle detection, registry lookup, уникальность/связность графа, совместимость I/O и компиляция графа — E2;
- lifecycle transitions агентов, leases, ToolGateway и permission enforcement — E3;
- проверка подтверждающего span, противоречий и model invocation provenance — E4;
- физическая совместимость и конвертация единиц, точный допуск суммы состава, route rules, Pareto и DoE-алгоритмы — E5;
- адресные правила stale/invalidation — E7;
- IPC, renderer, SQLite, Electron wiring, генераторы файлов и production-вызов новых схем;
- исправление или расширение TypeScript baseline.

# Разрешённые файлы

- новые `src/main/orchestrator/materials/contracts/common.ts`;
- новые `goal.ts`, `graph.ts`, `evidence.ts`, `feedback.ts`, `agents.ts`, `tools.ts`, `materials.ts`, `package.ts`, `index.ts` в том же каталоге;
- новые tests/fixtures только в `src/main/orchestrator/materials/contracts/__tests__/`;
- эта карточка, task README, materials README и changelog;
- точные зеркальные копии `docs/materials-orchestrator/**` в Obsidian.

Production engine, worker, profiles, IPC, preload, renderer, БД, существующие контракты generic-профиля, npm dependencies/scripts, TypeScript/Vitest/build config и baseline manifest не изменяются.

# Решения по границам валидации

- Zod проверяет форму, локальные диапазоны и локальные cross-field-инварианты. Он не доказывает научную истинность.
- `VersionRef` проверяется только структурно; существование конкретной версии требует repository и не симулируется в M1.1.
- Единица обязана быть непустой, но размерность, совместимость и преобразование единиц относятся к M5.1.
- Состав проверяет диапазоны отдельных fractions и отсутствие нечисловых значений. Точный допуск суммы и правила basis относятся к M5.2.
- `model_prediction` в общем claim не получает выдуманных полей. Обязательный `ModelCardRefV1` обеспечивается специализированным `PropertyPredictionV1`; связь claim с invocation проверит provenance gate E4.
- UQ остаётся вложенным `PropertyPredictionV1.interval`/`PropertyObservationV1.uncertainty`: отдельные `UncertaintyV1` и `ExperimentV1` в 04 не определены и не создаются.
- `NodeSpecV1` используется под нормативным именем. Отдельные `TaskNodeSpec` и `PlanPreview` в M1.1 не изобретаются.
- Поле `stale` не добавляется объектам, где его нет в 04. Repository-envelope для stale-состояния требует отдельного решения M1.4/M7.
- Golden DoE содержит желательные поля, которых пока нет в `ExperimentDesignV1`; M1.1 не расширяет V1 shape молча.

# Критерии приёмки

1. Экспортированы runtime-схемы и выведенные типы для всех объектов разделов 3–16 документа 04.
2. Нет ручного TypeScript-интерфейса, дублирующего Zod shape.
3. Все схемы и вложенные фиксированные объекты отклоняют неизвестные поля.
4. Каждый `schema_version` literal совпадает с именем V1-контракта.
5. Все валидные fixtures проходят `.parse()`; эталонная цель содержит `200 degC`, `100 h`, `250 degC`, четыре route family и максимум 8 экспериментов.
6. Все заявленные отрицательные fixtures отклоняются с адресными Zod issues.
7. `npm test` и `npm run build` проходят.
8. Baseline guard проходит, raw TypeScript не содержит новых или изменившихся fingerprints.
9. Generic regression остаётся зелёной; production не импортирует новый модуль до отдельной интеграционной карточки.
10. Документы репозитория и Obsidian совпадают по относительным путям и SHA-256.

# Правила остановки

Остановиться и запросить решение владельца, если:

- нормативный документ требует несовместимых shapes для одного V1-контракта;
- для выполнения приходится менять существующий production runtime, dependency или config;
- появляется новая TypeScript-диагностика;
- test/build/baseline не удаётся вернуть в зелёное состояние в разрешённых файлах;
- требуется invent field, который меняет публичный V1-контракт;
- задача расширяется до M1.2 или следующего milestone.

# Формат итогового отчёта

2. Результат targeted/full tests, build и baseline guard.
3. Подтверждение прохождения эталонных fixtures и отрицательных cases.
4. Список изменённых файлов и подтверждение отсутствия wiring в production.

# Отчёт о выполнении — 2026-08-28

M1.1 реализована и прошла повторное независимое ревью. Статус: `review`; M1.2 не запускалась.

## Решение владельца — 2026-08-28

Владелец принял M1.1 командой продолжить работу. Статус карточки изменён на `accepted`; после этого разрешён старт M1.2.

## Реализованный контрактный слой

- Созданы десять модулей: `common`, `goal`, `graph`, `evidence`, `feedback`, `agents`, `tools`, `materials`, `package` и публичный `index`.
- Реализованы все нормативные shapes разделов 3–16 документа 04, включая human gates, tools, доказательства, материалы, пакет и обратную связь.
- Все фиксированные объекты strict; неизвестные поля не удаляются молча, а дают Zod error.
- Все публичные TypeScript-типы выведены через `z.infer`; generic `AgentResultV1<TOutput>` сохраняет тип конкретного output contract.
- `SourceFragmentV1.locator` обязателен согласно нормативному shape.
- Новый модуль не подключён к production engine/worker/IPC: это намеренно чистый контрактный фундамент для следующих карточек.

## Локальные инварианты

- безопасные непустые ID, положительные версии и UTC ISO timestamps;
- конечные числа и обязательные единицы физических величин;
- непустой и упорядоченный `IntervalQuantity` в одной единице;
- цель содержит хотя бы одно свойство и маршрут, её веса неотрицательны и имеют положительную сумму;
- required/forbidden elements не пересекаются;
- `reported_fact` не проходит без `evidence_refs`;
- confidence/fractions находятся в допустимом локальном диапазоне;
- `none` нельзя смешать с реальными side effects;
- approved experiment package требует решение инженера;
- `request_changes` требует адресный `ChangeRequestV1`;
- SHA-256 источников и артефактов содержит ровно 64 hex-символа.

## Fixtures и контрактные проверки

- Полный golden `ResearchGoalV1` содержит режим `200 degC / 100 h / 250 degC`, четыре семейства маршрутов и предел 8 будущих экспериментов.
- Все материалы и составы в fixtures символические; ни одна тестовая запись не выдаётся за реальную рецептуру.
- Динамическая матрица автоматически сверяет barrel-export со всеми 44 экспортированными `*V1Schema`.
- Для каждой из 44 схем проверяются full fixture, root-minimal fixture, удаление каждого обязательного корневого поля и неверный тип; отдельные тесты закрывают вложенную strict-валидацию и cross-field-инварианты.
- Обязательные негативы включают missing unit/test temperature/ModelCard/critique/risks, `NaN`, `Infinity`, unknown enum, extra fields и reported fact без provenance.

## Границы результата

- JSON Schema, migration и repository envelope относятся к M1.2–M1.4.
- Известные пробелы нормативного ТЗ (`PlanPreview`, `plan_hash`, stale metadata и расширенные поля golden DoE) не заполнены самодельными V1-полями.
