# AntyFlow Materials R&D: поэтапный backlog реализации

**Статус:** исполняемый план  
**Правило:** одна задача — одна ветка или одна сессия Codex, один проверяемый результат

## 1. Граф эпиков

```text
E0 Защитный профиль и тестовый фундамент
 └─ E1 Контракты и версионированное хранение
     ├─ E2 Prepare → Preview → Approve
     ├─ E3 AgentSpec и ToolGateway
     ├─ E4 Knowledge & Memory Plane
     └─ E5 Материаловедческие сервисы
          E2 + E3 + E4 + E5
                  └─ E6 ExperimentPackage и Human Gate 2
                       └─ E7 Feedback, инвалидация и восстановление
                            └─ E8 Evals, импорт факта и усиление
```

После стабилизации E1 работы E3, E4 и детерминированная часть E5 могут идти параллельно.

## 2. Приоритетные риски существующего кода

Эти риски закрываются раньше доменных функций:

1. `webBuildPhase` может завершить текущий run до основного графа. В профиле `materials_rnd` это запрещается.
2. `engine.ts` передаёт `findCandidates({})`, а pipeline может выбрать `coder` просто из-за его присутствия. Материаловедческий путь обязан запрашивать capability явно.
3. JSON от LLM разбирается без runtime-схем. Все новые объекты проходят Zod.
4. Human approve сейчас может превратить проблемный локальный результат в `success` без научной перепроверки. Новые human gate утверждают версию объекта, а не обходят валидатор.
5. `vaultWrite` перезаписывает ключ. Утверждённые объекты переходят в append-only version store.
6. AnythingLLM сейчас выполняет ingestion, но не обеспечивает проверяемый `SourceSpan` для оркестратора.
7. Confidence в существующих режимах часто константный. Он не используется как материаловедческая неопределённость.
8. Оркестратор почти не покрыт тестами. До расширения создаётся FakeRuntime.

## 3. Общий Definition of Done задачи

Каждая задача считается завершённой, если:

- изменение ограничено заявленным scope;
- старый `generic`-оркестратор не сломан;
- каждый новый внешний вход проверяется Zod в main;
- есть позитивный и минимум один негативный автоматический тест;
- сетевые, LLM и научные вызовы в тестах заменены fixtures;
- `npm test` и `npm run build` проходят;
- в изменённых файлах нет новых ошибок TypeScript;
- обновлены документация, changelog и статус задачи;
- не логируются API-ключи, полные приватные документы и временный скрытый контекст;
- результат содержит список изменённых файлов, выполненных проверок и известных ограничений.

## 4. E0 — защитный профиль и тестовый фундамент

### `M0.1` — добавить `WorkflowProfile`

- **Зависимости:** нет.
- **Файлы:** новый общий модуль профиля и его unit-тест.
- **Результат:** единая Zod-схема `generic | materials_rnd` и безопасный default `generic` для отсутствующего значения.
- **Приёмка:** неизвестное значение отвергается; задача ещё не меняет IPC, UI и путь исполнения.

### `M0.2` — пронести профиль через все границы

- **Зависимости:** `M0.1`.
- **Файлы:** renderer → preload → main → WorkerData → engine.
- **Приёмка:** trace каждого run содержит профиль; подоркестратор наследует его.

### `M0.3` — выделить маршрутизацию профилей

- **Зависимости:** `M0.2`.
- **Новый модуль:** `src/main/orchestrator/profiles.ts`.
- **Приёмка:** generic использует старый путь; materials использует отдельную state machine.

### `M0.4` — закрыть обходы материаловедческого графа

- **Зависимости:** `M0.3`.
- **Результат:** `materials_rnd` не завершается через `webBuildPhase` и lecture-builder.
- **Тест:** spy доказывает отсутствие вызова этих путей.

### `M0.5` — создать FakeRuntime

- **Зависимости:** нет.
- **Новые файлы:** `src/main/orchestrator/__tests__/fakeRuntime.ts`, fixtures моделей и инструментов.
- **Приёмка:** DAG, budgets, human decisions, retrieval и tools тестируются без сети.

### `M0.6` — зафиксировать baseline

- **Зависимости:** `M0.5`.
- **Результат:** документированы текущие тесты, сборка и предсуществующие typecheck-ошибки.
- **Приёмка:** последующие задачи не могут списать новую ошибку на baseline.

## 5. E1 — контракты и версионированное хранение

### `M1.1` — создать модуль Zod-контрактов

- **Зависимости:** `M0.1`.
- **Путь:** `src/main/orchestrator/materials/contracts/`.
- **Минимум:** common, ResearchGoal, graph, agents, evidence, materials, package, feedback.
- **Приёмка:** fixtures из `04-data-and-api-contracts.md` имеют runtime parse.

### `M1.2` — экспортировать JSON Schema

- **Зависимости:** `M1.1`.
- **Результат:** версионированные схемы создаются из нормативных Zod-объектов.
- **Приёмка:** snapshot JSON Schema стабилен; ручное дублирование типов запрещено.

### `M1.3` — добавить SQLite-миграции материаловедческого профиля

- **Зависимости:** `M1.1`.
- **Файл:** `src/main/db.ts` или выделенный migration-модуль.
- **Приёмка:** новая и существующая БД открываются; rollback выполняется на временной копии.

### `M1.4` — реализовать version repository

- **Зависимости:** `M1.3`.
- **Результат:** create/read/list/supersede без изменения старой строки.
- **Приёмка:** утверждённую версию нельзя update; `N+1` ссылается на `N`.

### `M1.5` — append-only project events

- **Зависимости:** `M1.3`.
- **Результат:** каждое решение и изменение состояния записывается атомарным событием.
- **Приёмка:** состояние проекта восстанавливается воспроизведением событий fixtures.

### `M1.6` — структурированные ошибки

- **Зависимости:** `M1.1`.
- **Результат:** новые слои используют `StructuredFailureV1`, а не произвольные строки.
- **Приёмка:** retry определяется кодом и категорией, не парсингом текста.

## 6. E2 — Prepare → Preview → Approve

### `M2.1` — нормализатор `ResearchGoal`

- **Зависимости:** `M1.1`, `M1.4`.
- **Результат:** начальный текст создаёт draft и список открытых вопросов.
- **Приёмка:** отсутствие единиц или обязательного свойства не проходит незаметно.

### `M2.2` — агент уточнений

- **Зависимости:** `M2.1`, `M3.1` или временный строгий адаптер.
- **Результат:** компактная группа вопросов и явных defaults.
- **Приёмка:** default с высоким риском требует подтверждения инженера.

### `M2.3` — `PlanDraft` материаловедческого профиля

- **Зависимости:** `M2.1`.
- **Результат:** LLM предлагает стадии и capabilities, но не исполняемые функции.
- **Приёмка:** результат проходит `PlanDraftV1`.

### `M2.4` — компилятор типизированного графа

- **Зависимости:** `M2.3`, `M3.1`.
- **Новый путь:** `materials/graph/compiler.ts`.
- **Приёмка:** неизвестный NodeSpec, ToolSpec или контракт блокирует компиляцию.

### `M2.5` — валидатор и оценщик графа

- **Зависимости:** `M2.4`.
- **Приёмка:** обнаруживаются цикл, отсутствующая зависимость, несовместимый контракт, превышение бюджета; выдаются время, стоимость и риски.

### `M2.6` — Materials IPC prepare/compile

- **Зависимости:** `M2.1–M2.5`.
- **Файлы:** main, preload, `flow-api.d.ts`.
- **Приёмка:** `prepare` не запускает workers, научные инструменты и генераторы файлов.

### `M2.7` — UI уточнений и preview

- **Зависимости:** `M2.6`.
- **Рекомендуемый путь:** `src/renderer/src/orchestrator/` вместо дальнейшего разрастания одного shape-файла.
- **Приёмка:** инженер видит цель, допущения, граф, артефакты, цену, время и риски.

### `M2.8` — Human Gate 1

- **Зависимости:** `M2.7`.
- **Результат:** approval связан с `graph_version` и `plan_hash`.
- **Приёмка:** изменить goal или graph после approval и запустить старое разрешение невозможно.

## 7. E3 — AgentSpec, lifecycle и ToolGateway

### `M3.1` — разделить NodeSpec, AgentSpec и ToolSpec

- **Зависимости:** `M1.1`.
- **Результат:** три реестра с версиями и runtime-валидацией.
- **Приёмка:** прежние universal roles мигрируются как generic AgentSpec.

### `M3.2` — строгий capability matcher

- **Зависимости:** `M3.1`.
- **Приёмка:** все обязательные capabilities, права и контракты совпадают; `findCandidates({})` не используется в materials-пути.

### `M3.3` — исправить generic pipeline regression

- **Зависимости:** `M3.2`.
- **Результат:** наличие coder в каталоге само по себе не назначает его обычной задаче.
- **Приёмка:** отдельный регрессионный тест generic pipeline.

### `M3.4` — каталог шести MVP AgentSpec

- **Зависимости:** `M3.1`.
- **Источник:** `05-agent-and-tool-specs.md`.
- **Приёмка:** роли имеют входы, выходы, инструменты, запреты, TTL и бюджеты.

### `M3.5` — AgentLifecycleManager

- **Зависимости:** `M3.2`, `M3.4`.
- **Приёмка:** create/checkpoint/finalize/cancel/expire; во всех терминальных состояниях права отозваны.

### `M3.6` — ToolLease и ToolGateway

- **Зависимости:** `M3.1`, `M3.5`.
- **Приёмка:** allowlist, Zod input/output, timeout, retry, audit, запрет неизвестного инструмента.

### `M3.7` — model router

- **Зависимости:** `M3.4`.
- **Приёмка:** выбор tier имеет объяснение; переход на strong model учитывает бюджет и риск.

### `M3.8` — проверка AgentResult

- **Зависимости:** `M3.5`, `M3.6`.
- **Приёмка:** неправильная форма повторяет один узел; исчерпание попыток создаёт feedback, а не success.

## 8. E4 — Knowledge & Memory Plane

### `M4.1` — неизменяемый source store

- **Зависимости:** `M1.3`.
- **Результат:** оригинал, SHA-256, MIME, размер и metadata; повторный ingest не дублирует файл.

### `M4.2` — общие BM25/RRF primitives

- **Зависимости:** `M0.5`.
- **Результат:** переиспользуемые чистые функции извлечены из single-PDF поиска без изменения старого поведения.

### `M4.3` — project-level hybrid retrieval

- **Зависимости:** `M4.1`, `M4.2`.
- **Приёмка:** FTS и dense результаты объединяются; поиск изолирован `project_id`; возвращаются SourceSpan.

### `M4.4` — structured materials repository

- **Зависимости:** `M1.3`.
- **Приёмка:** составы, маршруты и PropertyObservation ищутся по полям, единицам и условиям, а не embeddings.

### `M4.5` — ContextBundle builder

- **Зависимости:** `M4.3`, `M4.4`.
- **Приёмка:** scoped context имеет версии, exclusions и token estimate.

### `M4.6` — provenance validator и commit gate

- **Зависимости:** `M4.1`, `M4.5`.
- **Приёмка:** reported fact без SourceSpan не получает статус verified; prediction требует ComputationRecord/ModelCard.

### `M4.7` — KAG-lite Evidence Graph

- **Зависимости:** `M4.4`, `M4.6`.
- **Приёмка:** типизированные узлы и рёбра; противоречия сохраняются; multi-hop путь воспроизводим.

### `M4.8` — память решений

- **Зависимости:** `M1.5`, `M4.7`.
- **Приёмка:** выбранные и отвергнутые альтернативы сохраняют причину, автора, версию и evidence.

## 9. E5 — материаловедческие сервисы

### `M5.1` — единицы и условия испытаний

- **Зависимости:** `M1.1`.
- **Приёмка:** конверсия детерминирована; несовместимые величины отклоняются.

### `M5.2` — каталог маршрутов и правил

- **Зависимости:** `M5.1`.
- **Приёмка:** пять семейств маршрута; причины невозможности машинно читаемы.

### `M5.3` — генератор CandidateDesign

- **Зависимости:** `M3.4`, `M4.5`, `M5.2`.
- **Приёмка:** кандидат всегда содержит composition + route; неподтверждённый состав имеет статус hypothesis.

### `M5.4` — интерфейсы научных адаптеров

- **Зависимости:** `M3.6`.
- **Приёмка:** phase/microstructure/property adapters имеют ToolSpec и fixture implementation; недоступность возвращает `unknown`.

### `M5.5` — ModelCard и applicability

- **Зависимости:** `M5.4`.
- **Приёмка:** prediction без версии и domain check отвергается.

### `M5.6` — uncertainty aggregation

- **Зависимости:** `M5.5`.
- **Приёмка:** отдельно видны data, model и knowledge uncertainty; LLM confidence не используется.

### `M5.7` — стоимость и длительность

- **Зависимости:** `M5.2`.
- **Приёмка:** результат содержит assumptions и currency/unit; отсутствие тарифа видно как unknown.

### `M5.8` — детерминированный Pareto

- **Зависимости:** `M5.6`, `M5.7`.
- **Приёмка:** доминируемый кандидат отсутствует; причины компромисса объяснимы.

### `M5.9` — минимальный DoE

- **Зависимости:** `M5.8`.
- **Приёмка:** каждый опыт имеет цель, ожидаемую information value, стоимость и stopping rule.

OR-Tools и реальные Python-модели не блокируют первый вертикальный тест. Они подключаются после стабилизации интерфейсов.

## 15. Точки обязательного решения владельца

Реализация останавливается для выбора, если:

- требуется купить или принять лицензию на стандарт, базу или научную модель;
- предлагается включить сетевой сервис по умолчанию;
- меняется граница «без управления физическим оборудованием»;
- требуется несовместимая миграция пользовательских данных;
- предлагается заменить существующий TypeScript runtime другим оркестратором;
- реальный научный адаптер не имеет понятной области применимости или лицензии.
