# Эталонный сценарий: алюминиевая конструкционная пластина

**Статус:** golden scenario для разработки и приёмки  
**Назначение:** проверить поведение оркестратора, а не доказать правильность конкретной рецептуры

## 1. Исходный запрос инженера

> Подобрать несколько вариантов термостойкой и прочной алюминиевой конструкционной пластины с умеренной стоимостью. Сравнить разные маршруты изготовления, минимизировать число будущих физических опытов и подготовить полный пакет для инженерного утверждения.

## 2. Пилотные допущения

- номинальная работа: `200 °C`;
- выдержка: `100 h`;
- кратковременный пик: `250 °C`;
- оценка свойств при комнатной температуре и `200 °C`;
- целевой объект — пластина;
- возможные семейства маршрутов: прокат, литьё с деформацией, порошковая металлургия, аддитивное изготовление;
- все химические кандидаты в fixture обозначаются символически.

Эти значения нужны для воспроизводимого теста. Они не являются утверждённым режимом реального изделия.

## 3. Что намеренно отсутствует в первом запросе

Система должна обнаружить:

- нет минимальной прочности;
- нет требования к пластичности;
- не указаны размеры пластины;
- не указана доступность оборудования;
- не определён жёсткий или предпочтительный бюджет;
- не указан максимум физических экспериментов;
- не определено, допустимы ли дорогие микролегирующие элементы;
- не определена методика испытаний.

## 4. Ответы инженера в fixture

Для автоматического сценария используются фиксированные ответы:

- геометрия остаётся вне точного расчёта, используется стандартный купон/образец;
- свойства задаются как направления оптимизации, а не сертификационные минимумы;
- максимум будущих физических вариантов: 8;
- дорогие легирующие добавки допустимы только как отдельная дорогая альтернатива;
- все четыре семейства маршрутов разрешены для цифрового сравнения;
- система должна предложить применимые методы испытаний, но инженер утверждает их позднее;
- пилотные температурные допущения подтверждены только для демонстрации.

## 6. Fixture-корпус знаний

Корпус не должен содержать готовый «правильный ответ». Он содержит проверяемые условия для поведения системы:

1. источник с данными при комнатной температуре;
2. источник после выдержки при `200 °C`;
3. источник с близкой, но не совпадающей температурой;
4. две публикации с противоречащими выводами;
5. таблица со свойством без единицы;
6. таблица с единицей, но без температуры испытания;
7. корректная численная запись с точной страницей и ячейкой;
8. документ о технологическом ограничении одного маршрута;
9. fixture ModelCard с ограниченной областью применимости;
10. источник, который найден поиском, но не подтверждает предложенный claim.

Все тексты могут быть синтетическими и свободными от лицензионных ограничений. Для golden-теста важны страницы, spans и ожидаемые связи.

## 7. Символические кандидаты

Чтобы тест не выдавал фиктивную рецептуру за инженерную рекомендацию, используются обозначения:

- `AL-CAND-A` — базовое недорогое семейство;
- `AL-CAND-B` — семейство с повышенной термостойкостью и средней стоимостью;
- `AL-CAND-C` — дорогая микролегированная альтернатива;
- `AL-CAND-D` — deliberately infeasible fixture.

У каждого кандидата не менее двух маршрутов. Конкретные доли компонентов хранятся только в синтетическом fixture и имеют статус `hypothesis`.

## 8. Ожидаемый граф верхнего уровня

```text
Goal and constraints
  → Evidence and numerical data
  → Candidate families
      ├─ Route branch: rolling
      ├─ Route branch: casting + deformation
      ├─ Route branch: powder metallurgy
      └─ Route branch: additive
  → Feasibility + predictions + UQ
  → Cost and Pareto
  → DoE
  → Independent critique
  → ExperimentPackage
  → Human Gate 2
```

До первой стрелки исполнения находится Human Gate 1 с preview графа, времени, стоимости, рисков и артефактов.

## 9. Встроенные ошибки и ожидаемые реакции

### Ошибка A — значение без единицы

- `PropertyObservation` не проходит контракт.
- Feedback классифицируется как локальная ошибка.
- Повторяется только извлечение этой записи.
- После лимита запись остаётся excluded с причиной.

### Ошибка B — источник не подтверждает claim

- Provenance validator отклоняет proposal.
- Evidence-agent получает адресный запрос найти другой span или изменить формулировку.
- Claim не становится verified.

### Ошибка C — противоречащие публикации

- Создаются два claims и contradiction record.
- Критик видит конфликт.
- В package попадает неопределённость, а не скрытое усреднение.

### Ошибка D — маршрут невозможен

- `AL-CAND-D` с одним fixture-маршрутом получает `infeasible`.
- Причина ссылается на route rule и входные constraints.
- Этот вариант не участвует в Pareto, но остаётся в журнале rejected alternatives.

### Ошибка E — модель вне области применимости

- Prediction получает applicability `outside`.
- Число не используется как надёжное значение целевой функции.
- Candidate может остаться как high-uncertainty hypothesis.

### Ошибка F — дорогой кандидат

- `AL-CAND-C` не удаляется, если стоимость является предпочтением, а не hard constraint.
- Он отображается как дорогая альтернатива на фронте компромиссов.

### Ошибка G — временный timeout инструмента

- ToolGateway делает не больше разрешённого числа повторов.
- После лимита Feedback Hub выбирает fallback, replan или human escalation.

### Ошибка H — агент предлагает новый подузел

- Предложение сохраняется как ChangeRequest.
- Оркестратор проверяет NodeSpec, бюджет и влияние.
- Только он создаёт GraphVersion N+1.

## 10. Ожидаемый фронт Парето

Golden-тест не фиксирует научный рейтинг реальных сплавов. Он фиксирует математическое поведение:

- `AL-CAND-A` условно лучше по стоимости;
- `AL-CAND-B` условно лучше по балансу свойств;
- `AL-CAND-C` условно лучше по одной термостойкой метрике, но хуже по цене;
- заведомо доминируемый fixture-кандидат отсутствует;
- для каждого оставшегося варианта есть объяснение компромисса.

## 11. Ожидаемый DoE

План содержит не более восьми будущих опытов. Каждый опыт указывает:

- CandidateDesign version;
- изменяемые факторы;
- фиксированные параметры;
- запланированные измерения;
- методику или статус «требует утверждения»;
- estimated cost;
- expected information value;
- какую неопределённость опыт должен уменьшить;
- stopping rule.

DoE является цифровым планом. Он не запускает оборудование.

## 12. Содержание ожидаемого пакета

`ExperimentPackageV1` включает:

1. ResearchGoal и решения инженера;
2. подтверждённые и оспариваемые claims;
3. source manifest;
4. candidate matrix;
5. маршруты и причины исключения;
6. predictions, applicability и UQ;
7. cost/risk matrix;
8. Pareto set;
9. ExperimentDesign;
10. CritiqueReport;
11. открытые вопросы;
12. ArtifactManifest;
13. Human Gate 2 decision после утверждения.

## 13. Проверка адресной инвалидации

После первого пакета fixture-инженер меняет вес или предел стоимости.

Должны стать `stale`:

- cost comparison, если изменился тариф или лимит;
- Pareto ranking;
- DoE, если он зависел от бюджета;
- critique и package;
- производные артефакты.

Не должны стать `stale` автоматически:

- оригиналы источников;
- SourceSpan;
- корректные фазовые результаты;
- состав и маршрут, если они не менялись.

После изменения composition version дополнительно инвалидируются зависящие route checks, predictions и UQ.

## 15. Чек-лист успешного сценария

- [ ] Неполный запрос приводит к вопросам.
- [ ] Pilot assumptions явно подтверждаются человеком.
- [ ] Preview появляется до исполнения.
- [ ] Запуск без Gate 1 невозможен.
- [ ] Агент создаётся только через capability request.
- [ ] Tool без lease отклоняется.
- [ ] Каждый verified fact имеет SourceSpan.
- [ ] Число без единицы исключается.
- [ ] Противоречия не скрываются.
- [ ] Недоступная модель возвращает unknown.
- [ ] OOD prediction маркируется.
- [ ] Невозможный маршрут объяснимо отклоняется.
- [ ] Дорогая альтернатива не скрывается.
- [ ] Pareto не содержит доминируемых вариантов.
- [ ] DoE объясняет ценность каждого опыта.
- [ ] Критик создаёт адресную правку.
- [ ] Package проходит контракт и provenance checks.
- [ ] Gate 2 устанавливает только инженер.
- [ ] Артефакты имеют один package ref.
- [ ] Изменение стоимости вызывает адресную инвалидацию.
- [ ] Ни один путь не создаёт команд физическому оборудованию.
- [ ] Повторный run даёт структурно эквивалентный результат.

## 16. Критерий прохождения golden scenario

Сценарий считается пройденным, когда он три раза выполняется через FakeRuntime без сети, все acceptance checks зелёные, package проходит Zod-схему, опубликованные claims имеют provenance, оба human gate нельзя обойти, а generic-профиль продолжает работать по прежнему пути.
