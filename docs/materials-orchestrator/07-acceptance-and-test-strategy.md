# AntyFlow Materials R&D: приёмка, тестирование и Definition of Done

**Статус:** нормативное ТЗ  
**Цель:** сделать качество проверяемым без субъективного «выглядит разумно»

## 1. Definition of Ready задачи

Задача готова к передаче Codex, если:

- имеет один результат;
- перечисляет зависимости;
- указывает разрешённые файлы или модули;
- ссылается на конкретные контракты;
- содержит позитивный и негативный критерий приёмки;
- объясняет, что не входит в scope;
- не требует неизвестного внешнего доступа;
- все решения владельца уже приняты либо явно обозначены как stop condition.

## 2. Definition of Done задачи

Задача завершена, когда:

1. реализован заявленный результат и только он;
2. внешние входы валидируются в main;
3. добавлены unit-тесты и отрицательный тест;
4. интеграция протестирована через FakeRuntime или временную БД;
5. не добавлены скрытые заглушки и безусловный success;
6. тестовый адаптер помечен как fixture;
7. существующий generic-профиль проходит регрессию;
8. `npm test` проходит;
9. `npm run build` проходит;
10. новые ошибки TypeScript отсутствуют относительно baseline;
11. документация и changelog обновлены;
12. в итоговом отчёте перечислены изменённые файлы, проверки и ограничения.

## 3. Уровни тестов

### 3.1. Контрактные тесты

Проверяют Zod-схемы, JSON Schema, миграции версий и структурированные ошибки.

Обязательные отрицательные случаи:

- отсутствует единица;
- отсутствует температура испытания;
- `NaN` или `Infinity`;
- неизвестный enum;
- ссылка на несуществующую версию;
- reported fact без SourceSpan;
- prediction без ModelCard;
- package без critique или risks.

### 3.2. Unit-тесты

Проверяют чистую логику:

- DAG и cycle detection;
- capability matching;
- plan hash;
- unit conversion;
- route rules;
- Pareto dominance;
- DoE ranking;
- feedback classification;
- dependency invalidation;
- retry limits.

### 3.3. Интеграционные тесты main/worker

Используют FakeRuntime, фиксированные model responses и временную SQLite.

Проверяют:

- маршрутизацию профиля;
- prepare без исполнения;
- approval binding;
- AgentRun lifecycle;
- ToolGateway;
- version repository;
- project isolation retrieval;
- package builder;
- event replay.

### 3.4. Renderer и IPC

Проверяют:

- main отклоняет неверный payload независимо от renderer;
- старые ноды открываются как generic;
- preview отображает все обязательные поля;
- кнопка запуска недоступна без Gate 1;
- статус approved недоступен без Gate 2;
- отмена не блокирует соседние ветви;
- после перезапуска UI восстанавливает версии и решения.

### 3.5. End-to-end golden scenario

Один фиксированный сценарий алюминиевой пластины выполняется без сети и создаёт структурно эквивалентный `ExperimentPackageV1`.

Golden-тест сравнивает структуру, версии, связи и обязательные значения. Он не требует буквального совпадения случайных ID и timestamp.

### 3.6. Evals качества

После MVP добавляются:

- retrieval recall@k;
- precision подтверждающих SourceSpan;
- доля claims с корректным provenance;
- точность классификации feedback;
- качество маршрутизации моделей;
- стоимость одного полного run;
- согласованность артефактов;
- устойчивость к противоречивым источникам.

## 4. Нормативные acceptance-сценарии

### `AC-01` — неполная цель

**Дано:** нет единиц целевого свойства и бюджета.  
**Ожидается:** статус `needs_clarification`, компактные вопросы, расчёты не запущены.

### `AC-02` — явное допущение

**Дано:** используется пилотный режим `200 °C / 100 h / 250 °C peak`.  
**Ожидается:** он записан как system default и требует подтверждения инженера.

### `AC-03` — неизвестный узел

**Дано:** PlanDraft предлагает незарегистрированный node type.  
**Ожидается:** compilation failure с адресной диагностикой, а не произвольное выполнение.

### `AC-04` — цикл в графе

**Дано:** две стадии зависят друг от друга.  
**Ожидается:** preview заблокирован; ребро не удаляется молча.

### `AC-05` — Gate 1

**Дано:** валидный граф без инженерного решения.  
**Ожидается:** `startRun` возвращает permission error.

### `AC-06` — устаревший approval

**Дано:** после approval изменён ResearchGoal.  
**Ожидается:** старый plan hash больше не разрешает запуск.

### `AC-07` — неправильный агент

**Дано:** узлу нужна `evidence_retrieval`, а роль имеет только `artifact_formatting`.  
**Ожидается:** роль не выбирается.

### `AC-08` — запрещённый инструмент

**Дано:** агент вызывает tool без lease.  
**Ожидается:** `denied`, аудит события, отсутствие фактического вызова.

### `AC-09` — TTL агента

**Дано:** heartbeat отсутствует дольше TTL.  
**Ожидается:** leases отозваны, AgentRun `expired`, feedback классифицирован.

### `AC-10` — provenance

**Дано:** reported fact без SourceSpan.  
**Ожидается:** Evidence Commit Gate отклоняет публикацию.

### `AC-11` — противоречие источников

**Дано:** два источника сообщают несовместимые результаты.  
**Ожидается:** обе позиции сохранены, создан contradiction record, значение не усредняется молча.

### `AC-12` — неправильная единица

**Дано:** прочность передана без единицы или в несовместимой величине.  
**Ожидается:** адресная contract/domain error и повтор только создавшего узла.

### `AC-13` — неизвестный научный результат

**Дано:** phase/property service недоступен.  
**Ожидается:** `unknown` с причиной, никакого числа от LLM.

### `AC-14` — выход за область модели

**Дано:** кандидат вне training domain.  
**Ожидается:** applicability `outside`, предупреждение и запрет отображения как надёжного прогноза.

### `AC-15` — технологически невозможный маршрут

**Дано:** operation противоречит оборудованию или форме заготовки.  
**Ожидается:** `infeasible` с машинно читаемой причиной; кандидат не попадает в Pareto.

### `AC-16` — дорогая альтернатива

**Дано:** кандидат превышает предпочтительный бюджет, но не запрещён жёстко.  
**Ожидается:** кандидат сохраняется как дорогая альтернатива и явно маркируется.

### `AC-17` — правильный Pareto

**Дано:** фиксированная матрица кандидатов.  
**Ожидается:** ни один возвращённый вариант не доминируется другим по всем критериям.

### `AC-18` — критик возвращает адресную правку

**Дано:** в одном prediction нет ModelCard.  
**Ожидается:** ChangeRequest направлен к конкретному узлу; весь проект не перезапускается.

### `AC-19` — Gate 2

**Дано:** валидный package без решения инженера.  
**Ожидается:** статус не выше `awaiting_package_approval`.

### `AC-20` — freeze

**Дано:** package утверждён.  
**Ожидается:** update запрещён; правка создаёт version `N+1` и новый hash.

### `AC-21` — согласованность артефактов

**Дано:** из одного package созданы Flow, MD и XLSX.  
**Ожидается:** совпадают package id/version, кандидаты и ключевые числа.

### `AC-22` — частичный сбой exporter

**Дано:** PPTX generator упал.  
**Ожидается:** научный package остаётся валидным, manifest отмечает failed artifact.

### `AC-23` — адресная инвалидация

**Дано:** инженер изменил предел стоимости.  
**Ожидается:** stale становятся cost, Pareto, DoE и package; literature и phase results остаются актуальными.

### `AC-24` — изменение состава

**Дано:** изменена composition version.  
**Ожидается:** stale становятся route-dependent calculations, predictions, Pareto и package.

### `AC-25` — ограниченный retry

**Дано:** tool трижды возвращает retryable timeout.  
**Ожидается:** после лимита feedback идёт в replan или human escalation; четвёртого скрытого повтора нет.

### `AC-26` — отмена

**Дано:** инженер отменяет run.  
**Ожидается:** новые tools запрещены, workers мягко останавливаются, leases отзываются, checkpoint сохраняется.

### `AC-27` — generic regression

**Дано:** старая orchestrator-нода без profile.  
**Ожидается:** открывается и выполняется по старому generic-пути.

### `AC-28` — отсутствие физического контроля

**Дано:** агент предлагает отправить команду оборудованию.  
**Ожидается:** отсутствует ToolSpec, вызов отклонён, предложение отражено как запрещённое действие.

## 5. Главный интеграционный тест

Рекомендуемый путь:

```text
src/main/orchestrator/materials/__tests__/materialsVerticalSlice.test.ts
```

Тест должен:

1. загрузить fixtures эталонного сценария;
2. создать draft;
3. получить вопросы и отправить ответы инженера;
4. скомпилировать preview;
5. доказать невозможность запуска без Gate 1;
6. утвердить точный plan hash;
7. выполнить граф через FakeRuntime;
8. проверить agents, tools, retrieval и provenance;
9. внедрить одну contract error и одну scientific revision;
10. получить Pareto и DoE;
11. собрать package;
12. доказать невозможность финального статуса без Gate 2;
13. утвердить package;
14. построить Flow, MD и XLSX manifest;
15. изменить budget constraint и проверить адресную инвалидацию;
16. убедиться, что generic regression остаётся зелёной.

Один fixture-run выполняется трижды и должен давать структурно эквивалентный результат.

## 6. Нефункциональные требования

### Надёжность

- ни один необработанный tool failure не завершает приложение;
- каждый ожидающий worker-запрос имеет timeout и ответ с ошибкой;
- terminal AgentRun не сохраняет активные leases;
- утверждённые версии неизменяемы;
- SQLite-операции изменения версии выполняются транзакционно.

### Производительность MVP

- preview на fixtures: не более 5 секунд без LLM и не более настроенного timeout с fixture LLM;
- локальный поиск по тестовому корпусу: p95 не более 2 секунд;
- одновременно активных AgentRun по умолчанию не более 4;
- ContextBundle не превышает лимит AgentSpec;
- renderer получает пагинированные журналы, а не весь run одним payload.

Это инженерные цели MVP, а не обещания для любого оборудования и размера корпуса.

### Безопасность и приватность

- ключи провайдеров никогда не уходят в renderer и trace;
- ToolGateway применяет deny-by-default;
- пути файлов нормализуются и ограничиваются project/source store;
- network tool указывает домен и цель;
- оригиналы пользователя не удаляются при перестроении индекса;
- telemetry не добавляется;
- физические control tools отсутствуют.

### Воспроизводимость

Для каждого результата сохраняются:

- версии цели, графа, контракта и AgentSpec;
- модель и версия prompt;
- ToolSpec и версия реализации;
- входные и выходные refs;
- источники и spans;
- seed детерминированного алгоритма, если применимо;
- стоимость, время и причины fallback.

## 7. Release gate MVP

Релиз блокируется, если:

- можно обойти Human Gate 1 или 2;
- есть published claim без provenance;
- prediction может появиться без ModelCard/applicability;
- агент может вызвать незарегистрированный tool;
- утверждённый package можно изменить;
- изменение основания не помечает зависимый package stale;
- vertical-slice или generic-regression тест падает;
- тестовый адаптер показывается как реальный расчёт;
- создаётся команда физическому оборудованию.
