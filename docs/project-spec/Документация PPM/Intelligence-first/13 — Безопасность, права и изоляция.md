# 13 — Безопасность, права и изоляция

## Активы

- аккаунты и сессии;
- задачи и комментарии;
- Canvas snapshots и semantic graph;
- Vault files и history;
- RAG chunks/vectors;
- agent prompts/results/actions;
- Git metadata и provider credentials;
- LLM provider credentials;
- backups и logs.

## Модель ролей

PPM не создаёт параллельные роли. Capabilities вычисляются из Plane workspace/project role и PPM policy.

Минимальная матрица уточняется по фактической Plane v1.4.2:

| Capability | Admin/Manager | Member | Guest/Viewer |
|---|---:|---:|---:|
| read Canvas/Vault/Brain | да | да | по project policy |
| edit Canvas | да | да | нет |
| upload/edit Vault | да | да | нет |
| change index policy | да | по policy | нет |
| query Project Brain | да | да | read-only policy |
| approve own allowed actions | да | да | нет |
| connect Git provider | да | нет | нет |
| create branch/PR | да | при repository permission | нет |

## Server-side authorization

Каждый PPM service использует общий permission adapter. Запрещено реализовывать проверки independently в frontend. Cached permission имеет короткий TTL и invalidation при membership change.

## Multi-tenancy invariants

1. Любая project row содержит project scope.
2. Любой object storage key разрешается через metadata и permission, не по угадываемому пути.
3. Vector retrieval получает обязательный project filter.
4. Agent run не расширяет права инициатора.
5. Git repository связывается только с project, который connection разрешает.
6. Admin другого workspace не получает доступ.
7. Background job несёт signed/internal scope и повторно проверяет актуальность source.

## Файлы

- allowlist MIME/extensions;
- server-side MIME sniffing;
- per-file/workspace size quota;
- quarantine state до завершения проверок;
- archive bomb/path traversal protection;
- parsers с CPU/memory/time limits;
- SVG sanitization или rasterized preview;
- no macro execution;
- signed downloads с коротким TTL;
- Content-Disposition и CSP;
- file hash для integrity/dedup.

## RAG и AI

- pre-retrieval ACL filter;
- source type/folder policy;
- prompt injection separation;
- PII/secret redaction policy;
- no raw credentials in prompt;
- citations validated against returned project sources;
- maximum context/token budgets;
- model provider allowlist;
- egress controls для self-hosted режима;
- deletion/access revocation immediately excludes source from answers.

## Git credentials

- OAuth/App installation preferred to personal token;
- tokens encrypted/held in secret manager;
- browser получает только connection status;
- минимальные provider scopes;
- webhook secrets rotatable;
- SSH private keys пользователя не принимаются;
- provider connection revoke прекращает sync/jobs.

## CSRF/XSS/CSP

- same-origin cookies с Secure/HttpOnly/SameSite согласно Plane stack;
- CSRF для mutations;
- Markdown/HTML sanitize;
- запрещён arbitrary iframe/embed по умолчанию;
- CSP ограничивает scripts, frames, media и connect sources;
- внешние ссылки получают safe rel attributes;
- Canvas labels и Mermaid content не исполняют HTML/JS.

## Audit events

Обязательно фиксируются:

- membership/permission changes;
- Canvas save conflict и destructive source actions;
- Vault upload/download/delete/restore;
- index policy/reindex;
- agent approval/application;
- Git connection/revoke;
- branch/PR creation through PPM;
- failed authorization;
- source/legal build identity.

Audit не хранит full file content, tokens, signed URLs и raw webhook bodies.

## Threat matrix

| Угроза | Защита | Проверка |
|---|---|---|
| подмена `project_id` | server membership check | cross-project API tests |
| RAG leakage | mandatory filter + source recheck | adversarial retrieval suite |
| prompt injection | data/tool separation | malicious document fixture |
| path traversal | UUID storage keys + normalized paths | `../`, absolute, unicode cases |
| stale overwrite | base version/ETag | concurrent edit tests |
| webhook replay | signature + delivery ID | repeat delivery test |
| token leak | secret store + log redaction | logs/browser inspection |
| malicious SVG/archive | sanitize/quarantine/limits | security fixtures |
| AI duplicate write | idempotency key | repeated approve test |

## Release blockers

- чужой project data появляется в любом ответе;
- signed URL работает после revoke/expiry дольше policy;
- provider token доступен browser/log;
- invalid webhook создаёт событие;
- файл выходит за Vault root/namespace;
- AI применяет write без recorded approval;
- public deployment не предоставляет required AGPL source/legal notice.
