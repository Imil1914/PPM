# 14 — Развёртывание, эксплуатация и резервирование

## Поддерживаемый контур

### Разработка

- Windows 10/11;
- Docker Desktop + WSL2 либо Linux host;
- Node/Python versions строго по Plane `v1.4.2` и PPM lockfiles;
- локальный `.env`, не коммитится;
- object storage и Redis поднимаются compose;
- test mail provider или console backend.

### Production/demo

- Linux VM;
- Docker Compose;
- HTTPS reverse proxy;
- постоянные volumes либо внешние managed services;
- точные image tags/digests;
- домен PPM;
- отдельный Git provider domain при self-hosted G2.

## Сервисы

Минимальный полный состав:

```text
proxy
ppm-web
plane-api
plane-worker
plane-scheduler
canvas-live              optional until realtime
postgres
redis/valkey
object-storage
ppm-index-worker
vector-index             if not pgvector
model-gateway            optional adapter service
```

External Git provider не входит в compose. Bundled Forgejo добавляется отдельным profile после G2 decision.

## Конфигурация

Группы переменных:

- public URLs/domain;
- Plane database/Redis/object storage;
- PPM feature flags;
- Canvas limits/realtime;
- Vault size/type quotas;
- index/embedding/completion profiles;
- Git provider client IDs/secret references;
- email;
- observability;
- backup destination/retention.

`.env.example` содержит только безопасные placeholders и комментарии. Production secrets не печатаются startup script.

## Feature flags

```text
PPM_BRAND_ENABLED
PPM_CANVAS_ENABLED
PPM_VAULT_ENABLED
PPM_BRAIN_ENABLED
PPM_AGENTS_WRITE_ENABLED
PPM_GIT_ENABLED
PPM_CODE_INDEXING_ENABLED
PPM_CANVAS_REALTIME_ENABLED
```

Отключение PPM Brain/Vault/Git не должно ломать Work Items Plane.

## Порядок запуска

1. Проверить config и pinned images.
2. Запустить Postgres/Redis/object storage.
3. Выполнить backup перед migration существующей среды.
4. Выполнить Plane migrations.
5. Выполнить PPM migrations.
6. Запустить API/workers.
7. Запустить web/proxy.
8. Проверить health/readiness.
9. Выполнить smoke read/write на тестовом project.
10. Проверить source/legal page и build identity.

## Health/readiness

### Liveness

Процесс отвечает и event loop/worker не завис.

### Readiness

- database reachable;
- migrations expected version;
- Redis/queue reachable;
- object storage bucket reachable;
- PPM app registry loaded;
- vector/LLM/Git показываются отдельными dependency states и могут быть degraded без падения core.

## Build identity

На странице admin/legal показываются:

- PPM version/commit;
- Plane upstream tag;
- Plane fork commit;
- schema versions;
- Canvas schema version;
- knowledge pipeline version;
- build time;
- active feature flags без secrets.

## Резервирование

### Что резервировать

- Plane/PPM Postgres;
- object storage Plane attachments;
- Vault blobs и versions;
- configuration manifests без secrets либо encrypted secrets backup;
- Git provider repositories/config в G2;
- legal build manifest.

### Что можно перестроить

- RAG chunks/vectors;
- thumbnails/previews;
- cached Git metadata;
- search indexes;
- derived summaries при наличии source references.

### Проверка восстановления

1. Восстановить backup в изолированную среду.
2. Запустить migrations только после копии.
3. Проверить login/project/Work Item.
4. Проверить Canvas current version.
5. Скачать Vault file и старую version.
6. Перестроить индекс и выполнить golden query.
7. Проверить Git links; tokens могут потребовать повторного подключения.

Backup считается существующим только после успешного restore drill.

## Обновление Plane

```text
fetch upstream
→ выбрать release tag
→ изучить security/changelog/migrations
→ rebase/merge в integration branch
→ разрешить PPM patch conflicts
→ baseline tests
→ visual/RAG/Vault/Git regression
→ migrate restored DB copy
→ staged deploy
→ smoke
→ release or rollback
```

Плавающий `latest` запрещён.

## Rollback

- предыдущие images/digests сохранены;
- migration compatibility проверена заранее;
- backup сделан и проверен;
- Canvas/Vault versions не уничтожаются rollback;
- новая PPM функция выключается feature flag;
- если schema rollback небезопасен, откатывается application code на forward-compatible version, а не выполняется destructive down migration.

## Наблюдаемость

Метрики:

- request latency/error rate;
- queue depth/job age;
- Canvas save conflicts;
- Vault upload/extraction failures;
- index freshness;
- RAG latency/degraded rate;
- citation count/no-source answers;
- agent run/action failure;
- Git webhook lag/failure;
- storage/database usage.

Logs структурированы и содержат `request_id`, project UUID только при необходимости, event/job IDs. File content, prompts по умолчанию, tokens и signed URLs не логируются.

## Release gate

- reproducible deploy from clean checkout;
- exact pinned versions;
- all critical services healthy;
- backup/restore smoke;
- cross-project security suite;
- no P0/P1 data-loss/auth defects;
- source/legal page accessible;
- known limitations published;
- manual owner acceptance.
