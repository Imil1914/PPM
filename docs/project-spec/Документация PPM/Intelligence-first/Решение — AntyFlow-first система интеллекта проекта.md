# Решение — AntyFlow-first система интеллекта проекта

## Решение владельца

PPM строится не как визуально узнаваемый Plane с дополнительной вкладкой. Plane Community остаётся внутренним функциональным движком, но пользовательская оболочка, визуальный язык, навигация, терминология и первый опыт принадлежат AntyFlow/PPM.

В каждый проект интегрируются:

- структурированная работа Plane;
- визуальный холст и семантические связи;
- файловый Project Vault в стиле Obsidian;
- отдельный Project Brain с RAG, графом и памятью;
- Git-контур, работающий со стандартными Git-клиентами, VS Code и Codex.

## Что сохраняется от решения v2

- Plane Community используется полностью как основа управления проектами;
- используется собственный fork и закреплённая версия;
- Plane владеет auth, workspace, projects и Work Items;
- PPM не создаёт вторую таблицу тикетов;
- поставка работает на одном домене и с одним входом;
- соблюдаются требования AGPL-3.0.

## Что изменяется относительно v2

| Было | Стало |
|---|---|
| пользователь после входа видит Plane | пользователь всегда видит оболочку PPM |
| AntyFlow — одна дополнительная вкладка | AntyFlow — дизайн-основа и главная модель взаимодействия |
| холст — визуальное дополнение | холст — «Мозг проекта» и центр контекста |
| документы в основном Plane Pages | единый раздел «Знания»: Plane Pages + Project Vault |
| RAG и агенты после первого релиза | минимальный Project Brain входит в демонстрационный вертикальный срез |
| Git — неопределённое далёкое расширение | Git-контур обязателен в архитектуре и реализуется поэтапно |

## Почему не создаётся собственный frontend с нуля

Полное повторение интерфейса Work Items, Cycles, Modules, Views, Pages, Analytics и Settings создаст второй продукт и уничтожит преимущество Plane. Нормативный путь:

1. использовать fork Plane Web;
2. добавить пакет `ppm-brand` с токенами и компонентами;
3. заменить shell, навигацию, assets и terminology;
4. постепенно адаптировать штатные экраны через небольшие изолированные патчи;
5. оставить бизнес-логику и API Plane.

## Почему не создаётся собственный Git-сервер

Git-объекты, pack protocol, SSH, pull requests, review, LFS, hooks и CI — отдельная предметная область. PPM реализует пользовательский слой и адаптер провайдера. Источником истины остаётся GitHub/GitLab/Forgejo. В будущем self-hosted режим строится на Forgejo либо другом утверждённом провайдере, а не на самописном хранении Git.

## Юридическая граница

Визуальный бренд Plane можно заменить в модифицированной сборке, но нельзя удалять обязательные copyright/license notices. Для сетевой модифицированной версии обеспечивается доступ к соответствующему исходному коду и инструкции сборки. Перед публичным коммерческим запуском выполняется юридическая проверка конкретной поставки.
