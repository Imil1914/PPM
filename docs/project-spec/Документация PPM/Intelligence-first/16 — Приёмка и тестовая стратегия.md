# 16 — Приёмка и тестовая стратегия

## Уровни проверки

1. **Static:** formatting, lint, typecheck, schema generation.
2. **Unit:** pure parsers, migrations, rank fusion, path/link resolution.
3. **Integration:** DB, object storage, Plane services, model/Git adapters.
4. **Contract:** API schemas, events, agent tools, provider normalization.
5. **E2E:** реальные user journeys.
6. **Security negative:** попытки выйти за scope.
7. **Visual:** screenshots и a11y.
8. **Operations:** restart, backup/restore, rollback.

## Golden test space

Создать два workspace/project либо минимум два private projects:

- `ROBOT` — задачи, Markdown, PDF и repository fixture;
- `BIO` — отдельные данные с уникальным marker, который никогда не должен появиться в ROBOT.

Пользователи:

- owner/admin;
- member ROBOT;
- member BIO;
- viewer ROBOT;
- outsider.

Fixtures не содержат реальных секретов или персональных данных.

## Сквозные сценарии D0

### E1. Регистрация и бренд

Пользователь проходит sign up/onboarding, создаёт project и не видит Plane branding на основном пути. Legal page доступна.

### E2. Work Item

Создаёт Work Item, меняет state, перезагружает страницу. Данные сохранены Plane.

### E3. Canvas

Открывает `Мозг проекта`, создаёт note, добавляет Work Item, связывает их, перезагружает страницу. Позиции и связь сохранены.

### E4. Безопасное удаление projection

Удаляет work_item_ref. Work Item остаётся в разделе «Работа».

### E5. Vault Markdown

Создаёт folder/note, редактирует Markdown, создаёт wiki-link, перезагружает страницу. Backlink разрешён.

### E6. Vault PDF

Загружает PDF, открывает preview, включает indexing. Source становится ready или показывает диагностируемую ошибку без потери файла.

### E7. Project Brain

Задаёт вопрос по Work Item+Markdown+PDF. Ответ содержит не менее одной корректной citation и ведёт к точному source locator.

### E8. Изоляция

ROBOT user пытается запросить BIO Canvas/Vault/knowledge IDs напрямую. Получает deny/not found; BIO marker отсутствует в retrieval.

### E9. Restart

После restart доступны Work Item, Canvas current version, Vault files и index metadata. Derived index при необходимости перестраивается.

## Сквозные сценарии Git G1

- connect/revoke provider;
- list linked repository;
- webhook push with valid/invalid signature;
- auto-link commit by Work Item key;
- open/merged PR state;
- create branch/PR preview and idempotency;
- Canvas PR projection;
- code citation with commit SHA/path;
- revoked connection stops synchronization.

## Negative matrix

| Попытка | Ожидание |
|---|---|
| unauthenticated PPM API | 401/redirect без data |
| foreign workspace/project ID | 403/404 без metadata leakage |
| viewer Canvas/Vault mutation | deny |
| stale Canvas/Markdown version | 409, no overwrite |
| cross-project binding | validation deny |
| deleted source in query | не попадает в retrieval |
| malicious Markdown HTML | sanitized |
| `../`/absolute upload path | rejected |
| zip bomb/symlink | quarantined/rejected |
| prompt injection source | no unauthorized tool call |
| repeated agent approve | one mutation |
| invalid webhook/replay | rejected/no duplicate |
| provider/LLM secret request | secret never returned |

## RAG evaluation

Для каждого вопроса хранить:

- expected source IDs;
- acceptable answer facts;
- forbidden facts;
- citation requirements;
- retrieval mode;
- latency budget.

В release gate входят Recall@K, groundedness, citation correctness и zero cross-project leakage. Конкретные thresholds фиксируются после baseline evaluation и не снижаются молча.

## Visual/a11y

- screenshots на утверждённых viewport;
- light/dark themes;
- keyboard-only navigation;
- focus visibility;
- contrast;
- screen-reader labels для основных действий;
- reduced motion;
- no user-facing Plane string вне allowlist.

## Performance smoke

- 20 projects workspace;
- 1000 Work Items project list;
- 300 Canvas shapes;
- 1000 Vault entries;
- 10k knowledge chunks test dataset;
- concurrent Canvas saves;
- queue backpressure.

Это smoke targets, а не SLA. Реальные budgets утверждаются по замерам на целевой VM.

## Definition of Done карточки

- scope выполнен, out-of-scope не добавлен;
- migrations/contracts обновлены;
- unit/integration tests проходят;
- negative test для permission/data loss добавлен;
- UI имеет loading/empty/error states;
- документация и changelog обновлены при необходимости;
- manual smoke описан и выполнен;
- rollback/feature flag понятен;
- diff reviewable;
- статус не `accepted`, пока владелец не принял демонстрацию.

## Release blocker severity

- **P0:** утечка данных, потеря canonical data, auth bypass, secret leak, destructive AI action без approval.
- **P1:** основной user journey не работает, baseline Plane сломан, индекс выдаёт чужой/удалённый source, backup не восстанавливается.
- **P2:** неудобный fallback, визуальная ошибка, локализация, некритичная производительность.

Release запрещён при открытом P0/P1.
