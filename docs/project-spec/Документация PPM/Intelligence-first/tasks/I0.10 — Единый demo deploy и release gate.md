# I0.10 — Единый demo deploy и release gate

## Пользовательский результат

Демонстрационная PPM-система доступна по одному HTTPS-домену, имеет одну регистрацию и проходит вертикальный путь Plane engine → AntyFlow UI → Canvas → Vault → Project Brain.

## Зависимости

- I0.1–I0.9 review-ready;
- целевая Linux/Docker среда;
- домен/DNS/TLS и разрешение на публикацию;
- source/legal materials.

## Scope

- unified compose/proxy;
- pinned images/build manifest;
- production-like env template;
- migrations/start order/health;
- HTTPS/same-origin routing;
- persistent data volumes/services;
- two-project E2E;
- restart smoke;
- backup/restore smoke для demo data;
- legal/source page;
- known limitations;
- release/rollback runbook.

## Не входит

- production SLA/autoscaling;
- full pentest;
- complete visual tail;
- realtime Canvas;
- agents write actions;
- external/bundled Git provider;
- claim of production readiness.

## Порядок реализации

1. Сформировать exact build manifest.
2. Проверить compose config без вывода secrets.
3. Поднять чистую staging/demo среду.
4. Выполнить migrations.
5. Проверить all health/readiness.
6. Настроить same-origin HTTPS routes/cookies/CSRF/CORS.
7. Создать ROBOT/BIO fixtures/accounts.
8. Пройти E1–E9 и negative matrix D0.
9. Сделать backup и restore в изолированный stack.
10. Проверить source/legal page и build identity.
11. Опубликовать known limitations внутри demo.
12. Подготовить one-command/one-runbook rollback без destructive data action.

## Критерии приёмки

1. Один login/session для всех разделов.
2. PPM UI не показывает Plane brand на основном пути.
3. Vertical scenario D0 проходит.
4. ROBOT/BIO isolation доказана.
5. Restart не теряет canonical data.
6. Backup восстанавливает Work Item, Canvas и Vault file.
7. RAG index перестраивается из sources.
8. Source/legal page указывает точные commits/license.
9. Нет P0/P1 defects.
10. Владелец вручную принимает либо возвращает с замечаниями.

## Проверки

- full build/compose validation;
- migrations from empty and restored DB;
- E1–E9;
- security negative suite;
- visual main-path screenshots;
- backup/restore;
- dependency failure modes;
- source/secret scan;
- rollback rehearsal.

## Rollback

Вернуть предыдущие pinned images/config и выключить новые feature flags. Не удалять volumes или migrations. При несовместимой migration использовать проверенный backup/forward fix plan.

## Stop rules

- нет разрешения на внешний deploy;
- домен/TLS/secrets не предоставлены;
- source/legal page отсутствует;
- обнаружен P0/P1;
- backup не восстановлен;
- пользовательские данные теста нельзя безопасно отделить от реальных.

## Gate

Только владелец выставляет `accepted`. После этого открываются I1 и G0.
