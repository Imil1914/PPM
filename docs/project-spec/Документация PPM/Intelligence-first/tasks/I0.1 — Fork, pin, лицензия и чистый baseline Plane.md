# I0.1 — Fork, pin, лицензия и чистый baseline Plane

## Пользовательский результат

Есть воспроизводимый функциональный движок Plane, на котором работают регистрация, пространство, проект, задача, Page и attachment. PPM-код ещё не меняет поведение baseline.

## Зависимости и входы

- [../Решение — AntyFlow-first система интеллекта проекта](<../Решение — AntyFlow-first система интеллекта проекта.md>);
- доступ к GitHub для fork — только если владелец разрешил внешнее действие;
- Docker Desktop/WSL2 либо Linux;
- stable release `v1.4.2`.

## Scope

- зафиксировать текущее состояние AntyFlow branch;
- определить точную структуру workspace/repositories;
- создать/подключить Plane fork или подготовить локальный upstream clone;
- создать integration branch от `v1.4.2`;
- сохранить upstream remote;
- проверить `LICENSE.txt`, notices и source strategy;
- поднять немодифицированный Plane;
- зафиксировать команды, versions, env keys и smoke result;
- создать baseline tag/ref/commit manifest.

## Не входит

- ребрендинг;
- Canvas;
- Vault;
- RAG;
- Git product integration;
- публикация без отдельного разрешения.

## Порядок реализации

1. Прочитать root instructions обоих repositories.
2. Проверить branch, remotes, status и uncommitted changes.
3. Не переносить/удалять текущий AntyFlow код.
4. Получить Plane `v1.4.2` с сохранённой Git history.
5. Записать upstream URL, tag и commit в build manifest.
6. Создать безопасный local env из официального example.
7. Запустить штатные сервисы без PPM patches.
8. Выполнить migrations.
9. Создать тестовый instance/user.
10. Пройти golden baseline.
11. Выполнить restart и повторить read.
12. Зафиксировать resource usage и ошибки.
13. Не коммитить secrets/runtime volumes.

## Golden baseline

```text
sign up → workspace → project → Work Item → Page → attachment → logout/login → restart
```

## Критерии приёмки

1. Source identity содержит tag и commit.
2. Upstream history сохранена.
3. Plane запускается из clean checkout по документированному порядку.
4. Golden baseline проходит.
5. Данные переживают restart.
6. License/notices присутствуют.
7. Logs и repository не содержат secrets.
8. PPM patches отсутствуют в baseline commit.

## Проверки

- compose/config validation;
- health всех обязательных сервисов;
- официальные targeted tests/build, реально доступные в repository;
- ручной golden baseline;
- restart smoke;
- secret/generated-files inspection.

## Rollback

Baseline не меняет пользовательские данные вне локальной тестовой среды. Containers/volumes удаляются только по явному разрешению и после проверки точных targets.

## Stop rules

- release tag/commit не совпадает;
- нужны коммерческие/private components;
- official baseline не стартует;
- dirty worktree пересекается с планируемыми файлами;
- требуется удалить существующую рабочую копию;
- external fork/push не разрешён.

## Gate

I0.2 получает clean baseline, manifest и документированные команды. Статус `accepted` ставит владелец.
