# G0.1 — Repository links и ручные связи с Work Items

## Пользовательский результат

Project имеет один или несколько repository URLs, разработчик копирует стандартный clone URL, а branch/commit/PR можно вручную связать с Work Item без provider token.

## Зависимости

- I0.10 accepted;
- [../10 — Git и контур разработки](<../10 — Git и контур разработки.md>).

## Scope

- repository/link metadata models;
- project `Код` UI;
- validate HTTPS/SSH repository URLs;
- default repository;
- clone URL copy;
- manual branch/commit/PR canonical URL link;
- Work Item key convention help;
- basic Canvas repository/link projection;
- permissions/audit.

## Не входит

- OAuth/provider API;
- webhook;
- code browser;
- clone by server;
- repository creation;
- automatic status sync.

## Порядок реализации

1. Добавить generic repository/link models.
2. Реализовать project admin CRUD.
3. Validate schemes/hosts and normalize display.
4. Добавить `Код` empty/list/detail UI.
5. Добавить manual Git object link to Work Item.
6. Добавить Canvas projection metadata.
7. Проверить URL security and permissions.
8. Документировать VS Code/Codex standard flow.

## Критерии приёмки

1. Разработчик копирует рабочий canonical clone URL.
2. Repository metadata видна только project members.
3. Manual Git object URL связывается с Work Item.
4. Удаление link не удаляет repository/provider object.
5. Canvas projection открывает canonical URL.
6. PPM не получает credentials.

## Проверки

- URL validation/security;
- permission matrix;
- duplicate/default repository constraints;
- manual link CRUD;
- Canvas open;
- VS Code/Codex clone manual smoke на тестовом public/private provider согласно доступу.

## Rollback

Выключить Git feature. Metadata links сохраняются; внешние repositories не меняются.
