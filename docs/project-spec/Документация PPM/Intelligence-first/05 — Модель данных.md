# 05 — Модель данных

## Общие соглашения

- первичные ключи PPM: UUID;
- ссылки на Plane хранят UUID Plane без локальной копии сущности;
- все project-scoped таблицы содержат `workspace_id` и `project_id`;
- `created_by`/`updated_by` — Plane user UUID;
- timestamps — UTC в базе, локализуются в UI;
- удаление по умолчанию мягкое только там, где нужна история;
- secrets не хранятся в обычных таблицах;
- JSON-поля имеют `schema_version` и Zod/serializer validation;
- derived records содержат `source_version` или `content_hash`.

## Canvas

| `id` | UUID | PK |
| `workspace_id` | UUID | Plane workspace |

MVP: unique active canvas per `project_id`. После MVP допускаются дополнительные canvases только через миграцию и обновление UX.

## Git

### `ppm_git_connections`

Хранит provider type, installation/account metadata, secret reference, status и timestamps. Сам token/SSH private key в таблице не хранится.

### `ppm_repositories`

Provider repository ID, project scope, owner/name, default branch, clone URLs, visibility, sync cursor, last sync. Unique `(connection_id, provider_repository_id)`.

### `ppm_git_links`

Связь Plane Work Item или Canvas node с `branch/commit/pull_request/repository`. Provider object ID и canonical URL обязательны.

### `ppm_git_events`

Raw body не сохраняется бессрочно. Хранятся delivery ID, normalized event, payload hash, processing state, repository ID и timestamps. Unique `(connection_id, delivery_id)`.

## Миграционные правила

1. Каждая модель создаётся только migration-файлом.
2. PPM migrations не удаляют/переименовывают core Plane columns.
3. Backfill выполняется отдельной idempotent job.
4. Новая версия Canvas/agent JSON получает schema migration.
5. Индексные таблицы можно перестроить, но canonical Vault versions нельзя терять.
6. Down migration не используется как единственный rollback при потенциальной потере данных.
