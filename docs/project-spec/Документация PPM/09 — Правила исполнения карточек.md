# 09 — Правила исполнения карточек

> Историческая редакция v1. Актуальная очередь: [Plane-first/tasks/README](<Plane-first/tasks/README.md>).

## Единица работы

Одна карточка — один проверяемый результат. Карточка не должна незаметно включать соседние функции.

## Статусы

```text
planned → ready → in_progress → review → accepted
                         └──────→ blocked
```

- `planned` — задача определена, но зависимости не готовы.
- `ready` — можно начинать.
- `in_progress` — выполняется сейчас.
- `review` — технически завершена, ждёт проверки.
- `accepted` — владелец принял результат.
- `blocked` — есть подтверждённая внешняя блокировка.

## Порядок старта

1. Прочитать карточку и только названные зависимости.
2. Проверить актуальную ветку и рабочее дерево.
3. Уточнить внешний доступ, если он необходим.
4. Зафиксировать входной test/build baseline.
5. Перевести карточку в `in_progress`.
6. Внести минимальные изменения.
7. Выполнить автоматические и ручные проверки.
8. Обновить CHANGELOG и перевести карточку в `review`.
9. Не начинать следующую карточку без прохождения gate зависимости.

## Ветки

Рекомендуемые имена:

- `ppm/p0.1-web-foundation`;
- `ppm/p0.2-db-rls`;
- `ppm/p0.3-teams-projects`;
- `ppm/p0.4-board-tickets`;
- `ppm/p0.5-docs-files`;
- `ppm/p0.6-agents`;
- `ppm/p0.7-export`;
- `ppm/p0.8-release`.

Одна ветка может содержать несколько маленьких коммитов, но не должна смешивать две карточки.

## Обязательные правила

- Новые структуры имеют Zod-схемы.
- Изменение БД выполняется только миграцией.
- RLS создаётся одновременно с таблицей, а не «потом».
- Секреты остаются только на сервере.
- UI-строки MVP — по-русски.
- Agent write — только через draft и approve.
- Ошибка AI не ломает ручной CRUD.
- Нельзя объявлять тест пройденным без фактического запуска.
- Нельзя переводить карточку в `accepted` без владельца.

## Формат отчёта по карточке

1. Что реализовано.
2. Какие файлы и миграции затронуты.
3. Какие решения приняты исполнителем.
4. Какие тесты и команды реально выполнены.
5. Что проверено вручную.
6. Что не проверено и почему.
7. Известные ограничения и риски.
8. Статус `review` и готовность следующей зависимости.

## Борьба со scope creep

Если новая идея не нужна для acceptance текущей карточки, она записывается в backlog и не реализуется. Особенно это относится к:

- Git-хостингу;
- rich text;
- realtime cursors;
- сложным dashboards;
- дополнительным агентам;
- мобильному приложению;
- импорту всех типов файлов;
- переносу всех AntyFlow нод.
