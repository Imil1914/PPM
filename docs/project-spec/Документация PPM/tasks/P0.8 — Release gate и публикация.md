# P0.8 — Release gate и публикация

## Цель

Проверить и опубликовать demo MVP, честно обозначив ограничения и обеспечив повторяемость демонстрации.

## Зависимости

P0.6 и P0.7 в `review`; если P0.6 сокращена, минимум Project Reporter работает или явно отключён без ущерба CRUD.

## Scope

- production environment;
- миграции production DB;
- demo seed;
- E2E эталонного сценария;
- проверка двух аккаунтов;
- error/empty/loading states критических экранов;
- страница «О версии» и известные ограничения;
- rollback-инструкция;
- финальный HTTPS deploy.

## Критерии приёмки

1. A1–A8 из тестовой стратегии пройдены.
2. Нет P0/P1 по потере данных или межкомандному доступу.
3. Все обязательные страницы открываются по production URL.
4. Секреты отсутствуют в репозитории и client bundle.
5. Demo seed воспроизводим и не дублируется.
6. Документация запуска соответствует фактическому приложению.

## Проверки

- lint/typecheck/tests/build;
- RLS suite;
- E2E golden flow;
- clean-session smoke;
- mobile-width smoke;
- ручной export и file download.

## Не входит

SLA, pentest, нагрузочное тестирование production-класса, собственный Git-hosting и enterprise compliance.

## Gate

Карточка переводится в `review`. Только владелец после демонстрации переводит P0.8 в `accepted` и разрешает G1.
