# P0.2 — Auth, Postgres и RLS

## Цель

Обеспечить регистрацию, сессию и минимальную модель пространства с доказанной изоляцией данных.

## Зависимости

P0.1 в `review`; владелец подтвердил Supabase или выбрал эквивалентный backend.

## Scope

- Supabase client/server setup;
- email/password или magic-link auth;
- `profiles`, `workspaces`, `workspace_members`;
- миграции и seed двух пользователей;
- RLS и grants;
- protected `/app`;
- logout и обработка истёкшей сессии.

## Критерии приёмки

1. Пользователь регистрируется и входит.
2. Неавторизованный пользователь не читает workspace.
3. Участник читает только своё пространство.
4. Пользователь B не получает workspace A прямым запросом.
5. Service key отсутствует в client bundle.
6. Повторное применение миграций на чистом окружении успешно.

## Проверки

- auth integration test;
- RLS allow/deny для anon, member и outsider;
- production build;
- два аккаунта в разных browser sessions.

## Не входит

OAuth providers, SSO, billing, приглашения по email и команды.

## Gate

Негативный RLS-тест outsider подтверждён до старта P0.3.
