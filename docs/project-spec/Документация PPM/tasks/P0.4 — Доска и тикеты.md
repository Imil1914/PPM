# P0.4 — Доска и тикеты

## Цель

Реализовать основной рабочий цикл команды: создать тикет, назначить исполнителя, изменить и провести по Kanban.

## Зависимости

P0.3 в `review`.

## Scope

- `boards`, `board_columns`, `tickets`;
- номер `<PROJECT_KEY>-<sequence>`;
- title, Markdown description, priority, assignee, due date;
- create/edit/archive;
- перемещение между колонками и сортировка;
- optimistic UI с rollback при ошибке;
- activity events;
- при нехватке времени select статуса вместо drag-and-drop.

## Критерии приёмки

1. Тикет создаётся через UI и получает стабильный номер.
2. Изменения сохраняются после reload.
3. Перемещение не создаёт дубликат.
4. Нельзя назначить пользователя чужой команды.
5. Observer не меняет тикет.
6. Параллельные изменения не приводят к потере самого тикета.

## Проверки

- CRUD integration tests;
- move/reorder test;
- RLS allow/deny;
- 100 тикетов на одной доске;
- ручной reload и две сессии.

## Не входит

Cycles, modules, epics, dependencies, estimates, recurring tickets и сложные saved views.

## Gate

Сценарий `создать → назначить → переместить → reload` пройден.
