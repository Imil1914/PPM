# Решение — Web-first MVP вместо переноса Electron один к одному

> Решение отменено владельцем 2026-09-12 и заменено [Plane-first/Решение — Plane Community как ядро PPM](<Plane-first/Решение — Plane Community как ядро PPM.md>).

## Контекст

Существующий AntyFlow — локальное Electron-приложение с React/tldraw, IPC и локальным SQLite. Новая цель PPM — сайт с регистрацией, многими командами, общими проектами, серверным хранением и разграничением доступа.

Ограничение — получить демонстрируемый рабочий продукт за два дня: 2026-09-12 и 2026-09-13.

## Предлагаемое решение

Создать рядом с AntyFlow отдельный **web-first контур PPM**, а AntyFlow использовать как источник:

- UI-паттернов доски и нод;
- Zod-контрактов и правил миграций;
- модели AgentRun, трассировки и подтверждения действий;
- компонентов Markdown и визуальных представлений, которые можно безопасно вынести из Electron.

Для MVP:

- frontend и server routes — Next.js + TypeScript;
- Auth, Postgres, Storage и при необходимости Realtime — Supabase;
- публикация web-приложения — Vercel;
- простая Kanban-доска вместо обязательного переноса всего tldraw-холста;
- Git — только ссылка на репозиторий в проекте; полноценная интеграция после MVP.

## Почему не переносить текущий Electron напрямую

- Electron main/IPC и `better-sqlite3` не работают как многопользовательский web-backend.
- Локальный SQLite не обеспечивает изоляцию 5–20 команд на публичном сайте.
- Полный перенос tldraw-холста, всех нод и локальных sidecar-агентов не помещается в два дня.
- Попытка одновременно сделать auth, SaaS, файлы, тикеты, Git-хостинг и сохранить всю функциональность AntyFlow создаст недемонстрируемый полуфабрикат.

## Цена решения

- Появляется второй runtime: web рядом с desktop.
- Часть кода AntyFlow сначала переиспользуется концептуально, а не прямым импортом.
- После MVP потребуется выделить общий пакет контрактов и дизайн-компонентов.

## Альтернатива

Самый быстрый функциональный прототип — развернуть Plane Community Edition и добавить фирменный слой и агентную интеграцию. Это сокращает разработку тикетов и страниц, но делает PPM зависимым от архитектуры и AGPL-лицензии Plane. В двухдневном плане это запасной путь, если собственный вертикальный срез не достигает release gate к середине второго дня.

## Критерий принятия решения

Решение считается `accepted`, если владелец подтверждает одновременно:

1. Цель двух дней — рабочий demo MVP, а не production-ready SaaS.
2. Web-приложение может быть отдельным контуром рядом с AntyFlow.
3. Основной backend MVP — Supabase/Postgres, не локальный SQLite.
4. Git-хостинг не входит в срок 2026-09-13.

## Статус

`candidate` — можно начинать только обратимые подготовительные работы и карточку P0.1; выбор архитектуры и внешних сервисов должен быть подтверждён владельцем до подключения реальных данных и публикации.
