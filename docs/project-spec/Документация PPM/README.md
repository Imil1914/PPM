# PPM — документация web-first MVP

> Эта редакция заменена [каноническим Intelligence-first ТЗ v3](<Intelligence-first/README.md>). Промежуточная [Plane-first редакция v2](<Plane-first/README.md>) и эта web-first редакция v1 сохранены как история.

Эта папка фиксирует первоначальный план PPM: многокомандную web-систему управления проектами на базе идей AntyFlow и продуктовой модели Plane.

> Статус: `draft`. Документы описывают реалистичный демонстрационный MVP на 2026-09-12—2026-09-13. Это не обещание полноценного production-SaaS или собственного GitHub за два дня.

## Коротко о продукте

**PPM** — Project & Portfolio Management для проектной школы: единое пространство, где 5–20 команд ведут проекты, участников, доски, тикеты, документы, файлы и отчётность, а AI-агенты помогают готовить черновики и сводки.

## Что означает Plane

Здесь имеется в виду **Plane**, а не «plain»: открытая система управления работой, близкая по назначению к Linear/Jira. Из её модели заимствуются понятия workspace, project, work item, cycle и pages/wiki. PPM не должен копировать весь Plane в первом релизе.

В PPM используем русские термины:

- пространство — организация или проектная школа;
- команда — отдельная группа участников;
- проект — работа команды с целью и сроками;
- доска — представление тикетов по статусам;
- тикет / work item — единица работы;
- документ — редактируемый Markdown-материал проекта;
- файл — загруженный артефакт с метаданными;
- агент — управляемый AI-процесс, создающий черновик результата;
- Git-контур — связь с репозиториями, коммитами и pull request, но не собственный Git-сервер в MVP.

## Зафиксированные границы

- Один публичный web-адрес с регистрацией пользователей.
- Одно пространство проектной школы, 5–20 изолированных команд.
- У каждой команды — участники, проекты, доски, тикеты, документы и файлы.
- Экспорт первой версии: CSV по тикетам и Markdown-отчёт проекта.
- AI создаёт только проверяемые черновики; массовые изменения требуют подтверждения.
- Собственный Git-хостинг, сложная аналитика, биллинг, мобильные приложения и полноценный Obsidian-подобный граф не входят в двухдневный MVP.

## Правило изменения статусов

Карточка проходит `planned → ready → in_progress → review → accepted`. Статус `accepted` ставит владелец после демонстрации. Одновременно выполняется не более одной карточки критического пути.
