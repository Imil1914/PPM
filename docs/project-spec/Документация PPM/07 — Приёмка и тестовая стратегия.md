# 07 — Приёмка и тестовая стратегия

> Историческая редакция v1. Актуальная стратегия: [Plane-first/06 — Приёмка и тестовая стратегия](<Plane-first/06 — Приёмка и тестовая стратегия.md>).

## Definition of Ready карточки

Карточка готова к реализации, если указаны:

- конкретный результат;
- зависимости;
- разрешённые файлы/модули;
- критерии приёмки;
- способ автоматической и ручной проверки;
- явный список того, что не входит в задачу.

## Definition of Done карточки

- реализован только заявленный scope;
- входы валидируются;
- права доступа проверены позитивным и негативным тестом;
- миграция воспроизводима;
- build и относящиеся к карточке тесты проходят;
- нет секретов и service key в клиентском bundle;
- карточка переведена в `review`, но не в `accepted`;
- CHANGELOG содержит результат, проверки и ограничения.

## Сквозные acceptance-сценарии

### A1. Регистрация и пространство

Новый пользователь регистрируется, создаёт пространство и попадает на пустой список команд.

### A2. Изоляция команд

Пользователь A состоит в команде A. Пользователь B состоит в команде B. A не может получить проект, тикет, документ или файл B ни через UI, ни прямым API-запросом.

### A3. Проект и доска

Руководитель создаёт проект. Пять стандартных колонок появляются один раз. После reload проект не дублируется.

### A4. Тикет

Участник создаёт тикет, назначает исполнителя, меняет приоритет и переносит в `В работе`. Другой участник команды видит то же состояние.

### A5. Документ и файл

Участник создаёт Markdown-документ, связывает его с тикетом, загружает файл и скачивает его после reload. Пользователь другой команды получает отказ.

### A6. Агент

Project Reporter создаёт черновик со ссылками на источники. До approve новый документ не появляется. Повторный approve не создаёт дубль.

### A7. Экспорт

CSV содержит номер, название, статус, приоритет, исполнителя и срок. Markdown-сводка открывается как обычный текстовый файл.

### A8. Публичный релиз

Публичный HTTPS URL открывается в чистой сессии, позволяет зарегистрироваться и пройти сценарий A1–A5.

## Автоматические проверки MVP

```text
lint
typecheck
unit tests контрактов
database migration test
RLS allow/deny tests
API integration tests критического CRUD
production build
```

## Минимальная матрица RLS

Для `teams`, `projects`, `tickets`, `documents`, `files`, `agent_runs` проверить:

- unauthenticated → deny;
- member same team → разрешённый select;
- member other team → deny;
- observer write → deny;
- lead same team write → allow;
- service operation без проверенного инициатора → deny на уровне приложения.

## Ручной smoke

- Chrome/Edge desktop;
- ширина 390 px без критической потери функций;
- два аккаунта в разных сессиях;
- создание 20 demo-команд и открытие общего списка;
- 100 тикетов на одной доске без явного зависания;
- файл допустимого типа и файл выше лимита;
- отказ LLM и повторный запуск;
- reload на каждой основной странице.

## Release gate 0.1

Релиз можно показать внешнему пользователю, если:

1. A1–A8 пройдены.
2. Нет P0/P1 дефектов потери данных или доступа к чужой команде.
3. На сайте есть пометка `Demo / MVP` и известные ограничения.
4. Настроены production environment variables без раскрытия секретов.
5. Есть способ экспортировать данные.
6. Есть владелец пространства, который может восстановить управление проектом.

## Что не означает успешная приёмка

Успешный release gate не подтверждает production SLA, соответствие требованиям по персональным данным, нагрузочную устойчивость, резервное копирование файлов или готовность собственного Git-хостинга.
