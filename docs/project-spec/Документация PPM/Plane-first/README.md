# PPM Plane-first — историческое ТЗ v2

> Эта редакция заменена [каноническим Intelligence-first ТЗ v3](<../Intelligence-first/README.md>). Она сохранена для истории решений и больше не является исполнительной документацией.

Эта папка фиксирует промежуточное решение владельца сделать Plane Community основой продукта и первым пользовательским интерфейсом.

## Продукт в одном предложении

**PPM — это self-hosted Plane с полным штатным функционалом управления проектами и встроенным проектным холстом AntyFlow.**

После регистрации пользователь сначала попадает в интерфейс Plane. Внутри каждого проекта рядом с Work Items, Cycles, Modules и Pages появляется раздел **«Холст»**, где команда использует визуальную доску AntyFlow в контексте этого же проекта.

## Главный пользовательский путь

```text
Регистрация Plane
→ Workspace
→ Project
→ штатные Work Items / Cycles / Modules / Pages
→ вкладка «Холст»
→ ноды AntyFlow, связанные с work items и pages проекта
```

## Источник истины

- пользователи, роли, workspace и projects — Plane;
- work items, cycles, modules, pages, attachments и activity — Plane;
- визуальное расположение, связи и специфичные ноды AntyFlow — PPM Canvas;
- связь сущностей — `workspace_id + project_id + entity_id` Plane;
- AI-agent runs — PPM extension, работающая через разрешённые API Plane.

## Что означает «полностью интегрировать Plane»

1. В поставку входит полный исходный код Plane Community.
2. Система использует штатную регистрацию, workspace, projects, work items, cycles, modules, views, pages и аналитику Plane Community.
3. Plane становится первым экраном и основной оболочкой продукта.
4. Холст AntyFlow открывается из навигации конкретного проекта.
5. Данные тикетов не дублируются в отдельной PPM-БД.
6. Версия Plane закрепляется и обновляется контролируемо из upstream.

Это не означает механическое копирование файлов без истории. Нормативный способ — собственный fork Plane и подключение закреплённой версии в PPM.

## Границы первого релиза

- полный штатный Plane Community запускается без вырезания функций;
- PPM-брендинг минимален и не скрывает обязательные лицензионные уведомления;
- в проекте появляется вкладка «Холст»;
- холст сохраняется отдельно для каждого Plane project;
- на холсте можно увидеть work items проекта и создать work item;
- двойная регистрация отсутствует: используется auth Plane;
- единый публичный домен обеспечивается reverse proxy;
- глубокая двусторонняя синхронизация всех типов нод и AI-агенты идут после устойчивого вертикального среза.

## Правило статусов

`planned → ready → in_progress → review → accepted`. Статус `accepted` ставит владелец после демонстрации. Одновременно исполняется одна карточка критического пути.
