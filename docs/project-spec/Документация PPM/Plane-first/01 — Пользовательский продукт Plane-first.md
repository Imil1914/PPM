# 01 — Пользовательский продукт Plane-first

## Первый вход

1. Пользователь открывает PPM.
2. Регистрируется через штатный auth Plane.
3. Создаёт или выбирает workspace проектной школы.
4. Попадает на штатный обзор Plane.
5. Создаёт командные projects и приглашает участников.

Отдельной регистрации AntyFlow нет.

## Что пользователь получает от Plane

- workspace и управление участниками;
- projects;
- work items и подзадачи;
- состояния, приоритеты, исполнители и labels;
- board/list/calendar/timeline views, доступные в Community edition;
- cycles и modules;
- pages/wiki и attachments;
- inbox/intake, views, filters и analytics в доступном составе версии;
- штатные notifications и activity.

PPM не должен ломать или подменять эти сценарии.

## Что добавляет PPM

### Вкладка «Холст»

У каждого Plane project есть визуальное пространство AntyFlow:

- свободное размещение нод;
- стрелки и связи;
- заметки и документы;
- work-item ноды, связанные с Plane;
- изображения, PDF и другие поддержанные web-ноды;
- AI-ноды и агенты на следующих этапах.

### Проектный контекст

Холст всегда открывается внутри выбранного Plane project. Пользователь не выбирает project повторно, а права наследуются из Plane.

### Два представления одной работы

- Plane — структурированное управление задачами;
- AntyFlow — визуальное мышление, материалы и связи.

Один work item может отображаться на холсте несколько раз визуально, но остаётся одной сущностью Plane.

## Минимальный сценарий интеграции

1. Руководитель создаёт project в Plane.
2. Создаёт work item `ROBOT-1`.
3. Открывает «Холст» этого project.
4. Добавляет связанную карточку `ROBOT-1` на холст.
5. Создаёт рядом заметку и соединяет её стрелкой.
6. Из холста создаёт новый work item `ROBOT-2`.
7. Возвращается в Work Items и видит `ROBOT-2`.
8. Другой участник project открывает тот же холст.

## Роли

Продуктовые роли Plane используются без создания параллельной системы ролей. Разрешение на холст вычисляется из доступа к workspace/project:

- admin/manager — читать и изменять холст;
- member — читать и изменять в рамках штатных прав project;
- guest/viewer — только читать, если доступ Plane не разрешает изменение;

Точные названия и возможности ролей фиксируются по выбранной версии Plane во время карточки PF0.2.

## Не входит в первый вертикальный срез

- перенос всех Electron-only нод;
- локальные sidecars;
- общий холст между несколькими projects;
- offline-first;
- полная синхронизация comments/cycles/modules на холсте;
- AI-автоматизация без подтверждения;
- собственный Git-хостинг.
