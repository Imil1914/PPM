# Решение — Plane Community как ядро PPM

> Решение заменено [../Intelligence-first/Решение — AntyFlow-first система интеллекта проекта](<../Intelligence-first/Решение — AntyFlow-first система интеллекта проекта.md>). Plane сохраняется как внутренний движок, но больше не является первым или визуально главным интерфейсом.

## Решение владельца

Plane Community интегрируется в PPM как основная система управления проектами. После регистрации пользователь видит Plane, затем из конкретного проекта переходит на холст AntyFlow и использует оба интерфейса в едином проектном контексте.

## Архитектурная форма

Plane не копируется внутрь Electron-кода одним неотслеживаемым каталогом. Используется:

1. собственный fork `makeplane/plane`;
2. закреплённый стабильный tag/commit;
3. полный исходный код Plane в составе системы через fork/vendor-модуль;
4. PPM-изменения отдельными коммитами поверх upstream;
5. регулярное сравнение и контролируемое обновление upstream;
6. единая Docker-поставка и reverse proxy.

## Почему Plane становится ядром

- уже реализованы регистрация, workspace и роли;
- есть projects, work items, cycles, modules, views и pages;
- есть API, webhooks и self-hosting;
- не требуется заново писать систему тикетов и документации;
- разработка концентрируется на отличии PPM — холсте AntyFlow и агентном слое.

## Интеграция холста

В навигацию Plane project добавляется `Холст`. Маршрут получает текущие `workspace_id` и `project_id`, использует сессию Plane и загружает единственный активный canvas проекта.

На первом вертикальном срезе:

- холст создаётся автоматически при первом открытии;
- snapshot сохраняется по project ID;
- work items проекта можно вывести как связанные карточки;
- создание work item из холста вызывает Plane API;
- переход по карточке открывает штатный экран Plane.

## Источник истины

Plane остаётся владельцем work items и страниц. PPM Canvas не создаёт параллельные таблицы `tickets` или `documents`, иначе появятся конфликты синхронизации.

## Развёртывание

Plane — многосервисное приложение. Базовый вариант публикации — Linux VM с Docker Compose, Postgres, Redis, object storage и reverse proxy. Vercel/Supabase больше не являются основной архитектурой проекта.

## Лицензионное условие

Plane Community лицензирован под AGPL-3.0. Для публично доступной модифицированной версии должен быть предусмотрен доступ пользователей к соответствующему исходному коду и сохранены обязательные уведомления. До внешнего коммерческого запуска требуется отдельная юридическая проверка конкретной сборки и границы производного произведения.

## Статус
