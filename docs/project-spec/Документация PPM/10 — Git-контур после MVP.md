# 10 — Git-контур после MVP

> Историческая редакция v1. Git-контур будет перепланирован после приёмки Plane-first PF0.7.

## Главный вывод

«Аналог GitHub» нельзя считать одной функцией. GitHub объединяет хранение Git-репозиториев, права, pull request, review, issues, CI/CD, release, пакеты и безопасность. Создавать всё это самостоятельно в рамках PPM нецелесообразно.

## Рекомендуемая лестница

### G0 — ссылка на репозиторий

Срок: входит в MVP.

- поле `projects.repo_url`;
- кнопка «Открыть репозиторий»;
- ручная ссылка тикета на branch/commit/PR.

### G1 — интеграция с GitHub/GitLab

- OAuth или GitHub App;
- webhook push/PR;
- привязка PR к тикету по ключу `ROBOT-123`;
- отображение статуса PR и checks;
- activity event в PPM.

PPM не хранит Git-объекты, а зеркалит только метаданные.

### G2 — единый интерфейс разработки

- список репозиториев проекта;
- branches/commits/PR в PPM;
- создание ветки из тикета;
- release notes;
- агентное review как черновик комментария.

### G3 — собственный Git-хостинг при реальной необходимости

Не писать Git-сервер самостоятельно. Интегрировать специализированную платформу, например Forgejo/Gitea, и оставить PPM продуктовым фронтендом и оркестратором.

## Будущие сущности

| Сущность | Назначение |
|---|---|
| `git_connections` | подключение workspace к провайдеру |
| `repositories` | repository metadata |
| `ticket_git_links` | связь тикета с branch/commit/PR |
| `git_events` | нормализованный webhook event |
| `pull_requests` | cached PR metadata |
| `check_runs` | status CI checks |

Токены доступа шифруются и никогда не возвращаются в браузер.

## Критерии G1

- владелец подключает Git provider;
- push с ключом тикета появляется в активности тикета;
- PR показывает open/merged/closed и checks;
- webhook проверяет подпись и идемпотентность delivery ID;
- пользователь без доступа к проекту не видит repository metadata;
- отключение интеграции прекращает синхронизацию без потери PPM-данных.

## Что не делать

- не хранить пользовательские SSH-ключи в клиенте;
- не выполнять произвольные git-команды на основном web-сервере;
- не давать агенту merge без отдельного подтверждения;
- не дублировать issues одновременно в Git provider и PPM без правила источника истины;
- не начинать G1 до прохождения release gate P0.8.

## Источник истины

- работа, сроки, документы и отчёты — PPM;
- код, commits, branches и pull requests — Git provider;
- связь между ними — стабильный ключ тикета и webhook/API.
