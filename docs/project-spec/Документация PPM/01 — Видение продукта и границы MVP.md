# 01 — Видение продукта и границы MVP

> Историческая редакция v1. Актуальное ТЗ: [Plane-first/README](<Plane-first/README.md>).

## Продукт одним предложением

PPM — web-платформа проектной школы, где несколько команд планируют работу на досках, ведут тикеты, хранят документы и файлы, получают AI-сводки и выгружают состояние проектов.

## Для кого

- руководитель проектной школы;
- руководители 5–20 команд;
- участники команд;
- наблюдатели и эксперты, которым нужен доступ только на чтение;
- администратор системы.

## Иерархия продукта

```text
Экземпляр PPM
└── Пространство проектной школы
    ├── Команда
    │   ├── Состав и роли
    │   ├── Проект
    │   │   ├── Agile-доска
    │   │   ├── Тикеты
    │   │   ├── Документы
    │   │   ├── Файлы
    │   │   ├── Сводки и экспорт
    │   │   └── Ссылка на Git-репозиторий
    │   └── Другие проекты
    └── Другие команды
```

## Основная ценность

1. Руководитель видит, над чем работают все команды и где блокировки.
2. Каждая команда работает в своём изолированном пространстве.
3. Тикет связывает задачу, исполнителя, срок, документы и файлы.
4. История проекта не распадается между чатами, папками и таблицами.
5. Агент превращает накопленные данные в черновик отчёта или декомпозицию задачи.

## Что такое «Plane-подобная» модель

Plane использует workspace, projects, work items, cycles/modules и pages/wiki. В PPM первого релиза берётся только минимальное ядро:

- workspace → пространство проектной школы;
- project → проект команды;
- work item → тикет;
- board view → Kanban по статусам;
- pages/wiki → Markdown-документы проекта;
- cycle → опциональный спринт после базового MVP;
- module → крупный блок проекта после базового MVP.

## Обязательный MVP за два дня

- регистрация и вход;
- создание пространства, команды и проекта;
- список команд и участников;
- Kanban со статусами `Бэклог / Запланировано / В работе / Проверка / Готово`;
- создание, редактирование, назначение и перемещение тикета;
- Markdown-документы проекта;
- загрузка файлов и привязка к проекту или тикету;
- один безопасный агент «Сводка проекта» и один агент «Декомпозиция тикета»;
- экспорт тикетов в CSV и сводки в Markdown;
- публичный HTTPS-адрес;
- базовая изоляция команд и ролей.

## Если остаётся время

- комментарии к тикету;
- фильтры по участнику, статусу и приоритету;
- простая обзорная панель руководителя;
- приглашение участника по email;
- realtime-обновление доски;
- шаблоны документов и тикетов.

## Не входит в двухдневный MVP

- собственный Git-сервер и хранение репозиториев;
- визуальный diff, pull request review и CI/CD;
- полный клон Plane, Jira, GitHub или Obsidian;
- сложные cycles/modules/epics/roadmaps;
- rich-text редактор уровня Notion;
- полнотекстовый и векторный поиск по всем файлам;
- автономные агенты с правом менять проект без подтверждения;
- биллинг, SSO, enterprise-аудит, мобильные приложения;
- гарантии production SLA, нагрузочная и security-сертификация.

## Метрики успеха демонстрации

- за 15 минут новый пользователь проходит путь от регистрации до готового тикета;
- одновременно заведены минимум 5 команд, архитектура не ограничивает 20;
- участник команды A не видит приватные данные команды B;
- перезагрузка страницы не теряет тикеты, документы и файлы;
- руководитель выгружает CSV и Markdown-отчёт без ручного копирования;
- агент создаёт только черновик, который можно принять или отклонить.

## Главный риск

Двухдневный срок конфликтует с формулировкой «работает как законченный продукт». Поэтому release 0.1 определяется как **рабочий демонстрационный MVP с честно обозначенными ограничениями**.
